# 知识点掌握度系统 设计文档

## 1. 目标

给知了建立"知识点级掌握度"：学生错题/作答 → 定位知识点 → 算出 0-100 掌握分（练习 + 考试双证据）→ 展示 + 驱动推荐。这是"能力阈值观"落地第一层（知识点证据层）。

## 2. 核心模型（已与亮哥确认）

**掌握度 = 0~100 分，由全场景学习证据综合计算，规则明确、每条分数有证据可溯源。这是通用证据系统，不是只认平台自出题的玩具。**

### 2.1 证据源（知了六大类学习数据全纳入）

| 类别 | 现有数据 | 证据强度 | 作用 |
|---|---|---|---|
| 平台练习作答 | answers | 强 | 直接加减分 |
| 平台组卷考试 | exams + exam_records | 强 | 得分率直接计入 |
| 真实考试录入 | exam_records（录学校月考/期中/期末成绩） | 强 | 得分率直接计入 |
| 错题导入（外部题） | error_book + import_errors | 强 | 重错扣分、导入即关联知识点 |
| 学习素材 | materials（老师发的视频/资料） | 弱 | 抑制衰减（最近学了=没忘） |
| 笔记 | notes | 弱 | 抑制衰减 |
| 学习计划完成 | study_plan task 完成 | 弱 | 抑制衰减 + 活跃度 |

**强证据**（作答对错/考试得分）直接算分；**弱证据**（看了素材/写了笔记/完成计划）证明"最近在学这个知识点"，抑制遗忘衰减。

### 2.2 评分规则

```
知识点掌握分 = 60% × 考试证据分 + 40% × 练习证据分   （有考试时）
知识点掌握分 = 100% × 练习证据分                      （无考试时）

练习证据分（0-100）：
  初始 0 分
  答对：+6/8/10 分（易/中/难）
  答错：-4/6/8 分（易/中/难）
  连续答对 ≥3 次：额外 +2 分/次（鼓励稳定）
  下限 0，上限 100
  衰减：30 天无该知识点作答 → 每月 -5 分（遗忘曲线，减到 0 为止）

**考试证据（只算真实考试）**：exams 需区分"真实考试"与"错题导入产生的虚拟考试"——考试证据只认真实考试（exams.source_type='real'）。虚拟导入的题走错题/作答证据，不算考试。
```

**阈值（能力线）**：先判断**有无证据**——无证据 = `unknown`（不显示分数，避免全屏飘红）；有证据才评：<60 薄弱（没过线）| 60-85 学习中 | >85 掌握（过线）。阈值是配置参数，可调。

> 子代理审查修正（08-10）：数据稀疏时（多数学生只有 2-4 类证据），"没做过题的知识点"会误判为薄弱。必须区分"无证据"和"有证据但薄弱"。用 08-09 方案的 status 四态表达：new（无证据）/ learning / graduated / relapse，confidence 只在有证据时更新。

**难度**：questions / question_bank_items 现无 difficulty 字段 → 统一按中档（+8/-6）计算，等有难度数据再细分。

**示例**：小明"一元一次方程"：月考该知识点题 10 分得 8 分（考试证据 80）；近 30 天练习 5 题，3 对 2 错（练习证据 = 3×8 - 2×6 = 12，上限 100 之内）。掌握分 = 60%×80 + 40%×12 = 52.8 → **薄弱**，AI 推荐补这个知识点。

### 3.1 新表结构

```sql
-- 知识点表（树形，来源课标）
CREATE TABLE knowledge_points (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  subject VARCHAR(50) NOT NULL,       -- 数学/英语/语文…
  name VARCHAR(100) NOT NULL,         -- 一元一次方程
  parent_id BIGINT NULL,              -- 上级知识点（代数→方程→一元一次方程）
  source VARCHAR(20) DEFAULT 'manual',-- 课标/manual/ai
  UNIQUE KEY uq_subject_name (subject, name)
);

-- 题目↔知识点映射（替代/升级 JSON knowledge_tags）
CREATE TABLE question_knowledge (
  question_id BIGINT NOT NULL,
  source_type VARCHAR(20) NOT NULL,   -- questions / question_bank_items
  knowledge_point_id BIGINT NOT NULL,
  confidence INT DEFAULT 100,         -- AI 标注置信度
  PRIMARY KEY (question_id, source_type, knowledge_point_id)
);
```

## 4. 数据迁移（1 次性）

**顺序：数学先、英语题库后**（英语题库从未被作答，标了知识点也不产生掌握度证据，只有推荐价值，放阶段 1 再说）。

1. 提取现有 knowledge_tags → 清洗 → 导入 knowledge_points
   - **清洗规则**：去垃圾（"本地验收"）、同义词归一（"一元二次方程定义"→"一元二次方程"、"根与系数关系"→"韦达定理"）、定层级（tags 是"代数/方程/一元一次方程/移项"混层平铺，需先定义谁是谁的父）
2. 数学 questions（73 题，已有知识点粒度）→ 建 question_knowledge 映射（**最高优先级**）
3. 英语题库（56 题，只有 ["英语"]）→ 放阶段 1，AI 辅助标注 + 人工审核
4. 旧 knowledge_tags JSON 保留不动（兼容），新数据走新表

**持续写入路径（防死表）**：create_exam / create_practice_exam / 错题导入（upsert_error_book）入库时，同步写 question_knowledge 映射——agent 建题带 knowledge_tags 入参时一并落映射表。

## 4.5 与现有模块的关系（防重复建设）

- **复用** `map_service.build_learning_map` 的采集逻辑（已按 tag 聚合错题/笔记/素材/计划），掌握度引擎做**增量计算层**，不重写聚合
- `diagnosis_service` 保持现状（按 tag 算错题率），掌握度引擎输出作为其补充信息
- 掌握度存储：**惰性计算**（读取时按 updated_at 折算衰减），不跑定时任务

## 5. 展示设计（前端小改）

- 错题页：每条错题下方显示"涉及知识点：一元一次方程 52 分 ⚠薄弱"
- 诊断页：学科知识点分数列表（按分数升序，薄弱在最上）
- 分数颜色：<60 红 / 60-85 黄 / >85 绿

## 6. 测试

- 评分引擎单元测试：纯函数，输入 answers/exam 数据 → 断言分数与阈值
- 迁移测试：真实 DB 数据抽样式验证
- 用例：全对 / 全错 / 连续答对奖励 / 衰减 / 有考试无考试

## 7. 长期规划（4 阶段）

| 阶段 | 内容 | 产出 |
|---|---|---|
| 0（本次）| 知识点表 + 映射 + 评分引擎 + 展示 | 学生能看到每个知识点分数 |
| 1 | 推荐升级：同知识点变式题推荐 | 治"会做原题、变式就懵" |
| 2 | 能力层：能力画像（从知识点证据推导）| 完整落地能力阈值观 |
| 3 | 内容扩展：课标知识点导入 + 更多学科题库 | 覆盖全科 |

每阶段独立见效，不依赖下阶段。

## 8. 非目标（本次不做）

- 不做能力画像（阶段 2）
- 不做实时流式更新（分数在作答/阅卷后计算即可）
- 不做知识点间的复杂依赖图（先平铺，树形够用）
