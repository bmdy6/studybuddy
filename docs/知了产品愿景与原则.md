# 知了产品愿景与原则

> 本文回答知了为什么存在、长期坚持什么，不描述页面、候选来源、API、数据库或具体功能实现。

## 一、为什么存在

学习产品不应要求学生先理解一组功能，再自己组织学习。学生真正需要的是：知道现在最值得学什么，并能自然地继续下去。

知了的长期定位是：

> **持续理解学生确认过的真实学习经历，在合适的时候告诉他下一步，并陪他完成。**

产品价值不来自展示多少 AI 能力，而来自每次使用后更理解这个学生，并让下一次学习更清楚、更容易开始。

## 二、核心承诺

学生每次进入知了，产品优先回答：

> **我现在应该继续什么，或者先学什么？**

家长进入知了或微信渠道，产品优先回答：

> **孩子最近真实发生了什么，我现在怎样陪伴更合适？**

## 三、真实事件原则

> **任何长期学习资产，都必须来自可追溯的真实学习事件；AI 或机器生成内容必须保留来源，不能伪装成学生确认事实。**

这条原则适用于所有渠道和功能：

- 错题来自学生确认过的题目、作答和批改结果，不来自 OCR 未确认的猜测。
- 笔记来自学生确认或修改后的草稿，不由 Agent 自动保存。
- 学习画像来自多次可追溯事件，不来自一次聊天推断。
- 家长成长摘要引用已确认事件，不声称学生“应该已经学会”。
- 学习地图展示证据，不允许 Agent 无依据写入“已掌握”。

没有真实事件时，可以形成待确认建议，不能形成长期事实。

默认情况下，计划、错题、笔记和画像等会改变正式业务状态的资产仍由学生或家长确认后保存。用户已明确授权两个低操作负担例外：

- 每日 AI 摘要可以根据当天结构化证据自动生成和入库，标记为 AI 或确定性摘要；摘要只是对事实的表达，不升级为学生确认事实，也不能反向成为新的学习证据。
- 素材机器识别结果可以自动保存并供 Agent 使用，标记为 `machine_extracted` 并保留 provider、置信度和不确定点；机器内容不能升级为 `verified`，人工修正或确认稿仍具有更高优先级。

## 四、Invisible AI

AI是产品内部能力，不是要求用户理解的功能目录。

学生看到的是：

- 继续学习。
- 开始复习。
- 我卡在这里。
- 完成今天。

而不是：

- 调用 Agent。
- 生成同类题。
- AI 分析错因。
- 自动整理笔记。

Agent可以识别、解释、组织、生成草稿和追问，但不能把推断写成学生事实。已授权自动保存的日报和机器素材必须保留来源与证据边界。

## 五、体验是状态，事实是事件

学生感受到的是连续状态，例如等待、学习、复盘和结束；系统可信依据来自具体发生过的事件，例如学生提交了一次作答、确认了一篇笔记或完成了一项计划。

“已掌握”“需要复习”“最近进步”等都是从证据推导出的状态，不是不可追溯的 AI 结论。

这是一条产品和数据原则，不代表当前决定采用完整 Event Sourcing 架构。是否建设事件存储、重放机制或派生状态基础设施，必须在技术 Spec 和 ADR 中另行论证。

## 六、不新增孤立功能

任何新能力进入方案前必须回答：

1. 它属于学习主流程的哪个阶段？
2. 它产生或消费哪些真实学习事件？
3. 它改善学生当前学习或家庭陪伴的哪一部分？

回答不了时，不新增页面、菜单或 Agent 工具。

## 七、长期边界

- 不以“AI 能做什么”倒推产品需求。
- 不把更多入口、图表或自动生成内容当作产品进步。
- 不用无法解释的分数和颜色冒充学习事实。
- 不强迫学生为了喂数据完成额外记录。
- 不要求学生每天手写完整回顾或逐份确认高置信机器素材；系统应自动整理，同时保留纠错入口和来源标记。
- 不把家长渠道变成高频监管工具。
- 不因为出现多个状态就提前建设通用流程引擎。

具体产品如何工作见历史文档《[知了 Learning Flow 产品模型](99-archive/2026-07-18/智学伴Learning%20Flow产品模型.md)》。

## 八、三层正反馈

> **反馈先服务孩子的成长感，再服务家长的陪伴，而不是先服务监管。**

- 第一层给孩子自己：让他知道今天比昨天进步了什么，不为家长。
- 第二层是 AI 的具体反馈：指出具体进步或接近正确之处，不是「你很棒」。
- 第三层才是家长反馈：系统帮家长理解孩子并引导怎么鼓励，而非只看分数。

第一层融在日常对话里，不做独立页面；成长必须有可追溯证据，不无依据夸奖。
