# 学习闭环实施顺序分析

> 配套《学习计划与试卷学习闭环问题分析-2026-07-22.md》。本文基于 2026-07-22 对现有代码的只读调研，确定 U-040~U-045 的实施先后顺序、依赖关系和每步的真实改动范围。当前仅用于确认顺序，未改业务代码。

## 一、目标与原则

- **基础设施优先**：先做被多个功能复用的底座，再接上层功能。
- **独立项快速止血**：和基础设施解耦的小 bug 顺手先修。
- **硬依赖驱动顺序**：有数据或接口依赖的，被依赖项先做。
- **每步可独立验收**：每批交付后能跑通一条完整路径，不积压半成品。

## 二、工作项总览

| 需求 | 名称 | 类型 | 基础设施 | 硬依赖 | 工作量 | 需迁移 |
|---|---|---|---|---|---|---|
| U-040 | Today 日期边界与计划同步 | bug 修复 | 否 | 无 | S | 否 |
| U-043 | 通用动态选择交互 | 交互底座 | 是 | 无 | M | v1 否 / v2 是 |
| U-041 | 计划详细描述与来源上下文 | 数据底座 | 是 | 无 | L | 是 |
| U-042 | 任务独立会话与选择性上下文 | 执行底座 | 是 | U-041, U-043 | L | 是 |
| U-044 | AI 任务完成判定与结果路由 | 完成闭环 | 否 | U-042, U-041 | L | 是 |
| U-045 | AI 正式试卷任务闭环 | 上层功能 | 否 | U-042, U-044 | L | 否 |

## 三、真实改动范围（基于代码调研）

### U-040 Today 日期边界与计划同步（工作量 S）

**根因（已确认）**

- `studybuddy-client/src/features/chat/components/TodayPlanPanel.tsx:133` 用 `plan.planned_date <= today` 过滤，导致逾期 active 计划继续进 Today。
- `listStudyPlans` 传 `status=''` 查全部，前端再过滤。

**改动点**

| 层 | 文件 | 改动 |
|---|---|---|
| 前端 | `TodayPlanPanel.tsx:133` | `<= today` 改 `== today` |
| 后端 | `app/features/p2/study_plan.py` `list_due_study_plan_reminders` | AI 历史参考走独立查询口径，不污染 Today |
| 前端 | 创建计划成功后的刷新链路 | 确认 Today 刷新 |

**达到效果**

- 学生打开 Today 只看到今天的计划，不再被昨天的逾期任务误导。
- AI 仍知道历史未完成项并主动参考进新计划，但不占今天的进度。

**验收**

- 数据库有逾期 3 天 active 计划时，Today 显示空态。
- AI 被要求制定今天计划时，能引用历史未完成项。

### U-043 通用动态选择交互（工作量 M）

**现状（已调研）**

- 工具注册：`tools.py` 的 `ALL_TOOLS` + 角色白名单 `STUDENT_TOOLS`/`TEACHER_TOOLS`/`CHANNEL_GUARDIAN_TOOLS` + `tools_for_actor` 选择器。
- handler 注册：`handlers/__init__.py` 的 `_HANDLERS` 字典。**硬约束**：`tests/unit/test_agent_loop.py:94` `test_all_tools_have_handlers` 断言 `ALL_TOOLS` 名称 == `_HANDLERS` 键，漏注册必挂。
- 现有 `present_profile_question`：不落库，只回显入参 + `next_step`；`tool_result` 只存 `{tool_call_id, name}`，完整输出在同行 `content`。
- 前端：`MessageBubble.tsx:125` 按 `tool.name === 'present_profile_question'` 分支渲染 `ProfileQuestionCard`，数据源是 `tool.input`（不是 output）。
- 回传：选中值作为普通 user 文本消息发回 `POST /api/chat/sessions/{id}/messages`，`SendMessageRequest` 只有 `content: str`，**无专用回传接口**。

**决策：新增独立工具，不泛化 profile question**

泛化 `present_profile_question` 会大改前端分支、prompt 和测试。新增独立 `present_choice_question`，前端复用 `ProfileQuestionCard`，画像旧能力逐步迁移。

**分两期**

- **v1（进批次1，无迁移）**：纯展示，像 profile question 一样不落库。前端做"已点击即禁用"乐观控制。关键流程的确认仍靠 `create_study_plan` 现有 `confirmed` 门控兜底。
- **v2（进批次2.5，加迁移）**：新增 `chat_choice_interactions` 表，支持过期、单次使用、结构化回传、状态校验。

**v1 改动点**

| 层 | 文件 | 改动 |
|---|---|---|
| 后端 | `app/features/agent/tools.py` | 加 `_TOOL_PRESENT_CHOICE_QUESTION` schema，加入 `ALL_TOOLS` 和 `STUDENT_TOOLS` |
| 后端 | `app/features/agent/handlers/`（新模块或 learning.py） | 加 `_handle_present_choice_question` 协程 |
| 后端 | `app/features/agent/handlers/__init__.py` | `_HANDLERS` 注册（必做，否则测试挂） |
| 后端 | `app/features/agent/prompts.py` | 系统提示要求有限选项问题必须调用该工具 |
| 前端 | `MessageBubble.tsx` | 加 `present_choice_question` 分支，复用 `ProfileQuestionCard` + `TOOL_LABELS` |

**达到效果**

- 学生遇到选择问题直接点按钮，不用打字。
- 想法不在选项里就点“都不符合，自己输入”兜底。
- 计划协商、任务执行、试卷选择用同一套按钮，体验统一。

**验收**

- 所有有限选项问题显示动态按钮 + “都不符合，自己输入”。
- 点击选项自动提交并继续 AI，不需再点发送。

### U-041 计划详细描述与来源上下文（工作量 L）

**现状（已调研）**

- `study_plans` 表（`sql/012_study_plans.sql`）只有 `title`/`focus(256)`/`status`/`planned_date`/`created_by`，**无 description/context_refs/revision**。
- `create_study_plan`（`study_plan.py:97-142`）**两次 commit**：第一次写 plan 主记录，第二次写 items。第二次失败会留下空计划。
- **无计划级修改函数**：只有 `archive_study_plan` 和 `update_study_plan_item_status`（只改 item 的 status，不改内容）。
- router 无 `PATCH /api/study-plans/{plan_id}`。
- `focus` 没在 TodayPlanPanel 展示，`target` 也没展示。
- `ManualStudyPlanDrawer` 手动创建时 `focus=null`、`target=null`、`related_tags=[]`。

**改动点**

| 层 | 文件 | 改动 |
|---|---|---|
| DB | `sql/021_study_plan_fields.sql`（新建） | ALTER 加 `description TEXT`/`context_refs JSON`/`revision INT DEFAULT 1` |
| ORM | `app/models/p2.py` StudyPlan | 加三字段 |
| Schema | `app/features/p2/schemas.py` | `StudyPlan` 输出 + `CreateStudyPlanRequest` 加字段；新增 `UpdateStudyPlanRequest` |
| Service | `app/features/p2/study_plan.py` | `create_study_plan` 加 description/context_refs 参数，**两次 commit 改单事务**；新增 `update_study_plan`（含事务 + revision 乐观锁） |
| Router | `app/features/p2/router.py` | 新增 `PATCH /api/study-plans/{plan_id}` |
| Agent | `tools.py` + `handlers/learning.py` + `agent_loop.py` | 新增 `update_study_plan` 工具 + handler + dispatch |
| 前端类型 | `src/types/p2.ts` | `StudyPlan` interface 加字段 |
| 前端 API | `src/features/p2/api.ts` | `createStudyPlan` 扩展 + 新增 `updateStudyPlan` |
| 前端组件 | `TodayPlanPanel.tsx` | 展示 description |
| 前端组件 | `ManualStudyPlanDrawer.tsx` | 表单加 description 输入 |
| 测试 | `tests/unit/test_p2_service.py`、`tests/api/test_p2.py` | 更新 |

**达到效果**

- 每份计划有完整说明：目标、参考了什么、学生提了什么要求、为什么这么拆任务。
- 学生和 AI 都能随时回看，不靠记忆。
- 学生不满意能直接让 AI 改，改完 Today 立刻更新，不用重建多份。

**验收**

- 新建计划必填 description，落库后 Today 可展开查看。
- 修改计划标题/描述/任务后 Today 立即同步，且是单事务。
- 两次 commit 的空计划风险消除。

### U-042 任务独立会话与选择性上下文（工作量 L）

**现状（已调研）**

- `ChatSession` 无 `session_type`/`plan_id`/`plan_item_id`/`status`/`context_version`。
- `sessions.py` 的 `create_session` 对学生直接代理到 `get_or_create_student_primary_session`，**学生不能创建非主会话**。
- 上下文注入全在 `agent_loop.py:124-139`，按 `student_id` 不按 session：`_build_profile_context`/`_build_daily_learning_record_context`/`_build_learning_memory_context`/`_build_error_import_context`。
- `context_summary` 和 `context_summary_message_id` 是 per-session 字段，**已支持独立压缩**（task session 可独立滚动）。
- `CHAT_CONTEXT_MAX_CHARS=24000`/`RECENT_TURNS=8`/`SUMMARY_MAX_CHARS=3500`。
- 前端 `useStudentLearningFlow.ts:46` 的 `startLearning` 只填 input 框，**不切 session**；所有任务在同一主会话。
- `store.ts` 只维护一个 `sessionId`，无 task session 概念。

**改动点**

| 层 | 文件 | 改动 |
|---|---|---|
| DB | `sql/022_chat_session_type.sql`（新建） | 加 `session_type`/`plan_id`/`plan_item_id`/`status`/`context_version`；`plan_item_id` 唯一索引（允许多 NULL） |
| ORM | `app/models/chat.py` ChatSession | 加字段 |
| Service | `app/features/chat/sessions.py` | `create_session` 分流：主会话走原逻辑，task 会话走新函数（关联 plan_item_id，唯一约束） |
| Schema | `app/features/chat/schemas.py` | `SessionItem` 加字段；新增 `CreateTaskSessionRequest` |
| Router | `app/features/chat/router.py` | 新增"继续计划任务"端点（只传 plan_item_id，自动创建/恢复 task session + 触发 agent，不产生可见假用户消息） |
| Agent | `agent_loop.py` + `context.py` | 上下文注入按 `session_type` 分流：task 注入 plan description + item target + 相关证据，不灌全量画像；工具集按 task 类型裁剪 |
| 前端 | `store.ts` | 加 `activeTaskSessionId`；`switchSession` 区分 main/task |
| 前端 | `useStudentLearningFlow.ts` | `startLearning` 改为调"继续任务"API，而非填 input |
| 前端 | `api.ts` + `types` | 加 `continueTaskItem` API；`ChatSession` 类型加字段 |

**关键风险**

- 上下文继承：task session 需从主会话继承稳定画像短摘要，否则 AI 不知道学生是谁。
- 前端切换：store 当前只有一个 `sessionId`，需支持 main↔task 切换且不中断对方流。

**达到效果**

- 点“继续学习”就自动进入学习，AI 直接开口安排，学生不用再发消息。
- 不同任务互不串线，做数学不会被上一项英语干扰。
- AI 只看当前任务相关内容，回答更准、成本更低。

**验收**

- 不同任务用不同 task session，切换后不串线。
- 点击继续学习后 AI 自动回复，无要求学生再发送的预填文本。
- 重复进入同一任务恢复原会话，不创建重复 session。

### U-044 AI 任务完成判定与结果路由（工作量 L）

**现状**

- `study_plan_items.status` 只有 `todo/done/skipped`，无 `in_progress`。
- 任务完成当前可由学生直接点按钮声明，无证据判定。
- 无 attempts 表。

**改动点**

| 层 | 文件 | 改动 |
|---|---|---|
| DB | `sql/023_study_plan_item_attempts.sql`（新建） | 新表 `study_plan_item_attempts` |
| ORM | `app/models/p2.py` | 加 `StudyPlanItemAttempt` 模型；`StudyPlanItem.status` 加 `in_progress` |
| Service | `app/features/p2/study_plan.py` 或新模块 | attempt 创建、评估、结果路由（passed/needs_retry/blocked） |
| Agent | `tools.py` + handler | 提交证据工具（在线答案/照片/文字/思路） |
| Agent | `agent_loop.py` | AI 按任务 target/rubric 评估，写 attempt + 置信度，不直接置 done |
| 前端 | 任务卡片 | 移除"手动完成"，改为提交证据入口 |

**达到效果**

- 学生不能光说“做完了”就算完成，必须提交答案或思路。
- 做错的题自动进错题和复练，不会被糊弄过去。
- 真正掌握后才标记完成并进入下一项。

**验收**

- 学生只说“做完了”不会直接 done。
- 错误答案进 needs_retry，并按规则进错题或复练。
- 达标后才 done 并自动进下一项。

### U-045 AI 正式试卷任务闭环（工作量 L）

**现状（已调研）**

- 正式 Exam 已支持题目、在线答题、交卷、判分、错题本。
- `create_exam` 只在 `TEACHER_TOOLS`，学生 task session 无法生成自练卷。
- Agent 创建 published 试卷后不自动分发 assignment，学生看不到。
- 无试卷行动卡、无 PDF 下载、无 plan_item 关联。

**改动点**

| 层 | 文件 | 改动 |
|---|---|---|
| Agent | `tools.py` + handler | 新增受限 `create_practice_exam`（学生只能为自己 task session 生成，原子完成 Exam+Assignment+plan_item 关联） |
| Agent | 权限 | 加入 `STUDENT_TOOLS`，后端从 task session 解析学生，不接受任意 student_id |
| Service | `app/features/exams/service.py` | 修对象级权限；出卷+分发同事务 |
| 前端 | `MessageBubble.tsx` | 试卷行动卡（在线作答/下载PDF/稍后/重生成） |
| 后端 | PDF 接口 | 学生版无答案 PDF（嵌入中文字体） |
| 前端 | 照片回传 | 上传携带 exam_id+plan_item_id+attempt_id，映射回原卷 |

**达到效果**

- 学生在任务里能直接生成正式试卷练习，不用老师额外布置。
- 在线做、下载打印做、拍照回传三种方式都能自动批改。
- 批改结果自动回到任务，决定是否完成，不用手动对账。

**验收**

- AI 生成试卷真实落库、分发、关联任务。
- 行动卡直达在线答题。
- 学生可下载无答案 PDF。
- 交卷/批改结果进统一 attempt 路由。

## 四、依赖关系

```
U-040 (Today 日期边界) ─── 独立，无依赖
U-043 (动态选择 v1)  ─── 独立，无依赖
        │
        │ v2 状态持久化（批次2.5）
        ▼
U-041 (计划数据契约) ─── 独立，但 U-042 依赖它的 description
        │
        ▼
U-042 (任务会话) ─── 依赖 U-041(description 注入) + U-043(任务执行选择)
        │
        ▼
U-044 (完成判定) ─── 依赖 U-042(task session 记录证据) + U-041(任务 target)
        │
        ▼
U-045 (试卷闭环) ─── 依赖 U-042 + U-044(attempt 路由)
```

**关键硬依赖**

- U-042 的 task session 要注入 plan description → U-041 必须先有 description 字段。
- U-044 的 attempt 要挂在 task session 上 → U-042 必须先有 task session。
- U-045 的试卷要进 attempt 路由 → U-044 必须先有结果路由。

## 五、推荐实施顺序

### 批次1：止血 + 交互底座（U-040 + U-043 v1）

两项独立，可并行。

- **U-040**：改 `TodayPlanPanel.tsx` 过滤 + AI 历史参考独立查询。最快止血，用户立刻看到 Today 正确。
- **U-043 v1**：新增 `present_choice_question` 工具，纯展示无迁移。是所有"强引导、低输入"体验的交互底座。

**为什么先做这两项**

- 都独立、风险低、快速见效。
- U-040 解决截图最直接的错误。
- U-043 是后续计划协商、任务执行、试卷选择的共同底座，早做早受益。
- 都不需要数据库迁移，不阻塞后续。

**交付物**

- Today 只显示当天计划。
- 有限选项问题显示动态按钮 + "都不符合，自己输入"。

### 批次2：数据底座（U-041）

- 给 `study_plans` 加 `description`/`context_refs`/`revision`。
- 创建改单事务，新增计划级修改 API + Agent 工具。
- Today 展示 description，手动抽屉加输入。

**为什么在 U-042 前**

- U-042 的 task session 要注入 plan description，没有字段就没法注入。
- 是 U-044 任务完成标准（target）的数据载体。
- 顺带修掉创建计划两次 commit 的空计划风险。

**交付物**

- 新计划必填 description，可修改，Today 实时同步。

### 批次2.5：动态选择 v2 状态持久化（U-043 v2）

- 新增 `chat_choice_interactions` 表，支持过期、单次使用、结构化回传。

**为什么在这里**

- 批次3 的 task session 执行会重度用到选择确认，需要状态校验保证"旧按钮不能重复点"。
- v1 的乐观控制够批次1/2 用，v2 在 U-042 前补齐。

### 批次3：执行底座（U-042）

- 拆 main/task 会话，`plan_item_id` 唯一。
- 点击继续学习自动创建/恢复 task session + 触发 AI。
- 上下文按 `session_type` 分流，工具按任务裁剪。

**为什么在 U-041 后**

- 依赖 description 字段注入。
- 依赖 U-043 的选择能力。

**交付物**

- 不同任务用不同 task session，不串线。
- 继续学习自动触发 AI，学生不需发送消息。

### 批次4：完成闭环（U-044）

- 新增 `study_plan_item_attempts`。
- 证据收集 + passed/needs_retry/blocked 路由。
- 移除学生手动完成，改为证据判定。

**为什么在 U-042 后**

- attempt 挂在 task session 上。
- 依赖任务 target 做完成标准。

**交付物**

- 学生不能口头声明完成。
- 错误答案进错题/复练，达标才 done。

### 批次5：试卷闭环（U-045）

- 受限自练卷生成 + 自动分发 + 任务关联。
- 行动卡 + PDF + 拍照回传。
- 交卷结果进统一 attempt 路由。

**为什么最后**

- 依赖 task session + attempt 路由。
- 是最上层功能，建立在前四批之上。

**交付物**

- AI 试卷真实可用，线上线下统一收口。

## 六、关键决策点（需确认）

1. **U-043 工具形态**：新增独立 `present_choice_question`，还是泛化 `present_profile_question`？→ 推荐**新增独立**（泛化会大改前端和测试）。
2. **U-043 分期**：v1 纯展示无迁移先上，v2 再加状态表？→ 推荐分期，v1 进批次1。
3. **U-041 字段策略**：`focus` 保留还是废弃？→ 推荐**保留**作短摘要，新增 `description`。
4. **U-041 乐观锁**：用 `revision` 整数还是 `updated_at`？→ 推荐 `revision` 整数，语义清晰。
5. **U-042 task session 唯一性**：`plan_item_id` 唯一（重开复用），还是允许多 session？→ 推荐**唯一复用**，避免无限创建。

### 格式 bug 排查结论

U-040 验收时发现 adjust 路径 AI 回复没格式、“让 AI 帮我定”路径有格式。排查结论：

- **渲染层已统一**：所有 AI 回复走 `MarkdownContent`（react-markdown + gfm + breaks），`MessageBubble.tsx:169`；`normalizeCompactNumberedList` 兜底处理“编号挤一行”。没有“有的走有的不走”。
- **prompt 已强制 markdown**：`prompts.py` 的 `RESPONSE_FORMAT_PROMPT` 要求用 markdown 列表、每项单独一行、禁止编号挤一行。
- **根因**：adjust 场景 AI 违反 prompt，回了 `【】` + 紧凑数字（非标准 markdown），react-markdown 当纯文本渲染。
- **结论**：adjust 路径已删（PR #95），bug 不复现。渲染和 prompt 无需改动。
- **残留风险**：AI 偶发不守 prompt，其他场景可能偶发。若需彻底兜底，可选增强 `normalizeCompactNumberedList`（把 `【】` 转标题、挤一行的 `-` 子项展开），但有误转风险，暂不动。
