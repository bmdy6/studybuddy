## 决策 1｜自练卷结果如何回到学习闭环（P0-1）

### 选项与推荐

| 方案 | 内容 | 工作量 | 风险 |
|---|---|---|---|
| A ✅推荐 | 加查询工具让 AI 看到自练卷分数，进判完成证据；文案改诚实 | ~半天 | 低 |
| B | submit_exam 按分数阈值自动写 attempt + 置 status，真闭环 | ~1-2天 | 中（分数->掌握度映射规则要定） |
| C | A + submit_exam 写 attempt 不置 status，留 AI 综合判 | ~1天 | 中低 |

**推荐 A**：v1 先解决「AI 凭聊天猜、客观分被丢」的核心降级；真闭环（B）的分数映射规则是产品决策，不该仓促定，留 v2 配合拍照/PDF 一起做。

### 实现设计（方案 A）

**新增 Agent 工具 `query_practice_exam_result`**

- 位置：`app/features/agent/tools.py`（注册到 STUDENT_TOOLS + ALL_TOOLS）+ `handlers/learning.py` 或 `handlers/exam.py` 加 `_handle_query_practice_exam_result`
- schema：
  ```python
  _TOOL_QUERY_PRACTICE_EXAM_RESULT = {
    "name": "query_practice_exam_result",
    "description": "查询某个学习计划项最近一次学生自练卷的作答结果（分数/对错率/错题知识点），用于评估该任务是否真掌握。判 complete_task_item 前应先调它看客观证据。",
    "input_schema": {
      "type": "object",
      "properties": {
        "student_id": {"type": "integer"},
        "plan_item_id": {"type": "integer", "description": "学习计划项 id"}
      },
      "required": ["plan_item_id"]
    }
  }
  ```
- handler 逻辑：
  - `sid = _resolve_tool_student_id(args, role, db, teacher_id)`（student 取 JWT）
  - 校验 `plan_item` 归属：`plan.student_id != sid` -> error
  - 查 `ExamAssignment` where `plan_item_id=? and student_id=sid` order by `created_at desc` limit 1，只看 status in (submitted/graded)
  - 关联 `ExamRecord` 拿 `total_score`/`objective_score`/`pending_manual_count`；查该 exam_record 的 `Answer` 统计对错，聚合错题 `knowledge_tags`
  - 返回：
    ```json
    {
      "plan_item_id": 123, "exam_id": 45, "assignment_id": 67,
      "status": "submitted", "total_score": 85, "max_score": 100,
      "objective_correct_rate": 0.85, "objective_total": 20, "objective_correct": 17,
      "pending_manual_count": 2,
      "wrong_knowledge_tags": ["定语从句", "U5"],
      "submitted_at": "2026-07-23T16:00:00",
      "summary": "最近一次自练卷 85/100，客观题对错率 85%，错题集中在：定语从句、U5"
    }
    ```
- 不存在的兜底：无 assignment 返回 `{"found": false, "summary": "该任务还没有自练卷记录"}`，AI 据此退回纯对话证据。

**prompt 变更**（`prompts.py` 学生系统 prompt，complete_task_item 规则附近）：
- 加一句：「评估计划项完成前，若该任务关联过自练卷（create_practice_exam 出过卷），应先调 `query_practice_exam_result` 看客观分；客观分低（如对错率<60%）时倾向 `needs_retry` 并把错题知识点写进 evidence。」

**文案修正**（名实不符）：
- `docs/验收-学习闭环U040-U045-2026-07-23.md` 第 7 项标题/预期补注「v1：出卷+分发+AI 可查分；结果自动回写计划待 v2」
- 后续 PR-3 的 commit message 用「自练卷结果可查询（自动回写待 v2）」而非「闭环」

**改动文件**：`agent/tools.py`、`agent/handlers/learning.py`（或 `exam.py`）、`agent/prompts.py`、`docs/验收-*.md`
**测试**：`tests/unit/test_practice_exam.py` 加 3 用例（有 submitted assignment 返回分数、无 assignment 返回 found=false、越权 plan_item 被拒）

## 决策 2｜AI 完成判定的硬门槛严格度（P1-3）

### 选项与推荐

| 档位 | 内容 | 误判风险 |
|---|---|---|
| 1 松 | 纯 prompt，现状 | 高（AI 可偷懒标完成） |
| 2 ✅推荐 | handler 校验 confidence∈[0,1]；passed 强制 evidence 非空 | 低 |
| 3 严 | 2 + passed 要求 confidence≥0.7 否则降级 | 中（易误杀） |

**推荐档位 2**：给「必须留证据」的软硬结合，防偷懒又不误杀；固定阈值太刚性，家庭辅导场景 AI 信心标定本就不稳。

### 实现设计（档位 2）

**handler 校验加强**（`handlers/learning.py:_handle_complete_task_item`，在 assessment 枚举校验后加）：
```python
confidence = args.get("confidence")
if confidence is not None:
    try:
        confidence = float(confidence)
    except (TypeError, ValueError):
        return {"error": "confidence 必须是 0-1 的数"}
    if not (0 <= confidence <= 1):
        return {"error": "confidence 必须在 0-1 之间"}
if assessment == "passed" and not (args.get("evidence_summary") or "").strip():
    return {"error": "assessment=passed 时必须提供 evidence_summary（对话证据摘要）"}
```

**`evidence_summary` 下游消费**（让存档字段不再死）：
- `_build_task_context`（`context.py`）注入该 plan_item 最近一次 attempt 的 `assessment + evidence_summary`，让 AI 进入 task session 时知道上次判定结论与证据
- 查询：`StudyPlanItemAttempt` where `plan_item_id=?` order by `created_at desc` limit 1

**人工撤销入口**：
- `update_study_plan_item_status`（`study_plan.py:262`）校验集从 `{todo,done,skipped}` 扩到 `{todo,in_progress,done,skipped}`
- 加一个显式「撤销完成」语义：把 `done -> todo/in_progress` 时清 `completed_at`（已有逻辑，确认覆盖）
- 是否需要单独 API 端点？现状 `PATCH /api/p2/study-plans/{plan_id}/items/{item_id}/status` 已存在，扩枚举即可，无需新端点

**prompt 变更**（`prompts.py`）：
- complete_task_item 规则补 `blocked` 使用场景（学生卡住需帮助时用，不要退回 needs_retry）
- 补「passed 必须有 evidence_summary，confidence 要如实估」

**改动文件**：`agent/handlers/learning.py`、`agent/context.py`、`features/p2/study_plan.py`、`agent/prompts.py`
**测试**：`tests/unit/test_task_completion.py` 加 4 用例（confidence 越界 reject、passed 无 evidence reject、in_progress 可手动置、撤销完成清 completed_at）

## 决策 3｜家长试卷列表是否过滤学生自练卷（P2-3）

### 选项与推荐

| 方案 | 内容 |
|---|---|
| A ✅推荐 | teacher list_exams 只列 created_by=teacher，学生自练卷不进家长列表 |
| B | 保留但加「学生自练」标签，只读 |
| C | 现状（混入但管不了） |

**推荐 A**：家长管自己出的卷，学生自练卷是学生私域，混入干扰判断。监督需求靠学生详情页单独满足。

### 实现设计（方案 A）

**改动**：`app/features/exams/service.py` 的 `list_exams`（teacher 分支）
- 查询加 `Exam.created_by == teacher_id` 过滤（teacher_id 即 `user.id`）
- 确认 student 分支不受影响（学生看自己的 assignment，本来就只看分给自己的卷）
- 边界：teacher 出的卷 `created_by=teacher_id`，学生自练卷 `created_by=student_id`，过滤后家长列表只剩自己出的

**改动文件**：`features/exams/service.py`（`list_exams` teacher 分支）
**测试**：`tests/unit/test_exam_service.py`（或对应文件）加 2 用例（teacher 列表不含学生自练卷、学生视图不变）

## 决策 4｜是否允许家长代学生标任务完成（P2-4）

### 选项与推荐

| 方案 | 内容 |
|---|---|
| A ✅推荐 | handler 加 `if role != "student": raise`，仅学生可标完成 |
| B | 允许家长代标（低龄场景） |
| C | 家长代标置「待确认」中间态 |

**推荐 A**：U-044 核心是「AI 看学生对话充分度判掌握度」，家长没参与对话，代标的 evidence 是空的，违背设计。低龄操作靠 UI 解决（学生端一键「我做完了」），不是让家长代判。

### 实现设计（方案 A）

**改动**：`app/features/agent/handlers/learning.py:_handle_complete_task_item` 开头加：
```python
if role != "student":
    raise PermissionError("只有学生能标记任务完成（基于自己的学习对话证据）")
```

**工具注册调整**：`tools.py` 把 `complete_task_item` 从 `ALL_TOOLS` 移到仅 `STUDENT_TOOLS`（参考 `record_feedback` 的 `if role != "student"` 模式）
- 注意：`tools_for_actor`（`tools.py`）里 teacher 工具集不再含 `complete_task_item`
- prompt 家长系统 prompt 里去掉 complete_task_item 的描述（避免家长 AI 尝试调用被拒）

**改动文件**：`agent/handlers/learning.py`、`agent/tools.py`、`agent/prompts.py`（家长 prompt 去 complete_task_item 描述）
**测试**：`tests/unit/test_task_completion.py` 加 1 用例（role=teacher 调 complete_task_item 抛 PermissionError）
