# 学习计划与试卷学习闭环问题分析

> 本文根据 2026-07-22 的 5 张手机端真实使用截图、用户补充说明、当前产品原则和现有代码整理。当前仅用于确认问题、基础能力和实施顺序，不代表已经进入开发或已经实现。

## 一、本轮修正后的核心判断

上一版有四处判断需要修正：

1. **逾期计划是前端 Today 展示错误，不是 AI 不该知道。**
   - 昨天没有完成的计划，今天不能继续出现在 Today。
   - AI 制定今天计划时，应该知道历史上哪些任务没完成，并把它们作为参考。
   - 历史计划可以影响新计划，但不能直接占用今天的任务列表和进度。

2. **创建计划后需要支持修改，不只是“新计划替换旧计划”。**
   - 今天没有计划时，AI 和学生讨论确认后创建一份今日计划。
   - 学生创建后不满意，可以继续和 AI 商量并修改同一份计划。
   - 修改标题、描述、任务、时长或顺序后，Today 必须立即同步。

3. **“继续学习”不应继续依赖学生长期主会话和手工发送消息。**
   - 当前学生所有学习都进入同一个长期主会话，旧内容靠压缩摘要维持。
   - 这会让不同任务互相污染，并持续消耗上下文预算。
   - 推荐改成“主会话负责计划协商，每个计划任务有自己的任务会话”；点击继续学习后自动创建或恢复任务会话，并直接触发 AI 回复。

4. **任务完成不能只由学生点击按钮声明。**
   - 学生需要提交可判断的学习证据，例如在线答题、试卷照片、文字答案或思考过程。
   - AI 或确定性判分服务根据任务完成标准判断“通过 / 需要再练 / 卡住”。
   - 错误答案应进入错题、复练、讲解等后续路由，而不是直接把任务标成完成。

## 二、产品目标

智学伴的目标是让需要强引导的学生不用自己组织学习流程。学生进入产品后，只需要不断点击系统给出的下一步，必要时提交答案或照片，就能完成当天学习。

完整体验应当是：

1. Today 只展示今天的计划；历史未完成计划不展示，但 AI 制定新计划时会参考。
2. AI 用动态按钮询问学生时间、目标和偏好，学生点选即可。
3. AI 和学生讨论出一份带详细描述的计划，确认后真正落库到 Today。
4. 学生不满意时可以修改计划，修改结果立即同步 Today。
5. 学生选择任务并点击“继续学习”，系统自动进入该任务会话，AI 直接开始安排学习，不需要学生再发消息。
6. AI 只注入当前任务真正相关的计划描述、画像、历史记录和素材，其余信息按需用工具读取。
7. 学生提交作答证据，AI 或判分服务判断是否达到完成标准。
8. 错误答案进入错题和复练流程；通过后自动完成任务并进入下一项。
9. 需要正式练习时，AI 生成可在线作答、可下载 PDF、可拍照回传的试卷。

## 三、问题清单与修正方案

### P0-1：历史逾期计划错误显示在 Today

**截图现象**

- Today 显示“今日英语数学学习计划（已逾期 3 天）”。
- AI 已正确知道这是一份逾期计划，但前端仍把它当成今天任务展示。

**代码根因**

- `TodayPlanPanel.tsx` 使用 `planned_date <= today` 组装 Today 队列。
- 后端 Learning Flow 也把今天和逾期提醒放在同一候选列表。
- 现有 14 天后自动归档不能替代严格的 Today 日期边界。

**正确规则**

- Today 查询严格使用 `planned_date == today`。
- 到第二天后，无论昨天完成几项，Today 都从全新的当天计划开始。
- `planned_date < today` 的计划保留原状态和历史数据，不进入 Today，不占今天进度。
- AI 制定今天计划时可以主动查询最近历史未完成项，并决定是否重新安排其中一部分。
- “历史参考”与“Today 展示”必须是两个查询口径：
  - Today：只查今天。
  - AI 计划参考：查最近历史、未完成任务、相关错题和每日记录。

**验收**

- 数据库存在一份逾期 3 天的 active 计划时，Today 仍显示“今天还没有计划”。
- AI 被要求制定今天计划时，能说明“之前还有某项未完成”，但不会把旧计划直接放回 Today。

### P0-2：AI 创建或修改计划后，Today 没有同步

**截图现象**

- AI 声称已创建新计划，但 Today 仍显示之前的数据。
- 当前也没有完整的计划修改能力。

**代码根因**

- Agent `create_study_plan` 成功后没有触发 Today 数据失效和重新加载。
- 计划只有创建、归档、任务状态修改，没有“修改计划标题、描述和任务内容”的正式 API。
- Today、Agent 工具和手动计划表单各自管理刷新，缺少统一的计划变更事件。

**正确规则**

- 今天没有计划时，AI 确认创建后，新计划立即成为 Today 计划。
- 创建计划和开始学习是两个动作；创建成功只回到 Today，不自动开始讲题或出题。
- 学生不满意时，AI 应提供“修改今天计划”，更新同一份计划，而不是不断创建多份相似计划。
- 修改范围包括：计划标题、计划描述、任务标题、任务描述、预计时长、顺序、增加任务和移出任务。
- 每次创建或修改成功后，Today 自动刷新；刷新失败时给“重新加载 Today”按钮，但不得重复创建。

**数据一致性要求**

- 创建计划主记录和全部任务必须是一个事务，不能先提交空计划再逐项提交任务。
- 修改计划也必须是一个事务；部分任务修改失败时，原计划保持不变。
- 增加 `revision` 或使用 `updated_at` 做乐观锁，避免 AI、手动抽屉和另一个设备互相覆盖。
- Agent 工具返回 `plan_id + revision + changed_fields`，前端按同一计划刷新。

### P0-3：AI 讨论完后没有真正创建计划，而是直接开始学习

**截图现象**

- AI 和学生讨论学习安排后，直接在聊天里给阅读或填空练习。
- Today 中没有对应的新计划，学生也无法从计划再次进入。

**正确流程**

1. AI 用动态按钮问清今天可用时间、目标和要求。
2. AI 给出计划草案和详细描述。
3. 学生点击“按这个创建”。
4. Agent 必须调用正式计划创建工具并确认落库成功。
5. Today 自动显示计划。
6. AI 只回复“已经放到今天”，不直接执行第一项。
7. 学生从 Today 选择任务并点击“继续学习”后才开始执行。

**服务端门禁**

- 继续保留“近期计划草案 + 用户明确确认”的创建 guard。
- 新增工具结果约束：`create_study_plan` 成功后的下一步只能是刷新 Today，不能同轮继续生成练习。
- 如果模型只说“已创建”但没有真实 `plan_id`，前端不得显示成功状态。

### P1-1：计划缺少可持续使用的详细 description

**问题性质**

这是独立的数据能力，不只是页面少显示一行文字。

现有 `StudyPlan.focus` 最长 256 字，只适合短目标，不足以承载一份计划的完整上下文。计划需要新增正式的 `description TEXT`，作为学生、Today 和任务 AI 共同理解计划的持久化说明。

**description 必须包含**

1. 今天这份计划要达到什么结果。
2. AI 参考了哪些历史未完成计划或学习问题。
3. AI 参考了哪些已有画像、错题、每日记录、笔记或素材。
4. 学生明确提出了哪些要求，例如时长、内容、难度、学习方式或兴趣。
5. 计划为什么拆成这些任务，每项大概如何执行。

**示例**

> 今天用 40 分钟复习英语时态并做一次小测。参考了上次未完成的“一般过去时练习”、最近时态错题和学生希望结合唱歌视频学习的要求。先用 15 分钟完成时态阅读理解，再用 10 分钟复盘错题，最后生成一份 15 分钟试卷检验掌握情况。

**推荐数据设计**

- `study_plans.description TEXT`：给学生和 AI 阅读的完整计划说明，新计划必填。
- 保留 `focus`：作为列表中的一句短目标，向后兼容。
- `study_plan_items.target`：继续作为任务说明和完成标准，不新增重复字段。
- `study_plans.context_refs JSON`：保存精确来源引用，例如历史计划、素材、错题、笔记和每日记录 ID；description 负责可读，context_refs 负责可靠查询，不把数据库 ID 硬塞进自然语言。
- 老计划允许 description 为空并使用 `focus` 兜底；新创建和新修改的计划必须有 description。

**同步规则**

- Today 当前计划可展开查看 description。
- 任务会话启动时固定注入计划 description 和当前任务 target。
- 学生修改计划后，未开始任务使用新 description；正在进行的任务会话收到一次“计划已更新”上下文事件，不能继续使用旧要求。

### P1-2：长期主会话导致任务串线和上下文成本持续增长

**当前代码事实**

- 学生被 `primary_student_id` 唯一约束固定到一个长期主会话。
- 当前每轮最多仍会回灌 `CHAT_CONTEXT_MAX_CHARS=24000` 字符。
- 旧消息会被压成 `context_summary`，最近 8 轮保留原文。
- Agent 每轮还会注入画像、每日记录、学习记忆、素材摘要、错题和笔记摘要。
- 当前没有 `plan_id`、`plan_item_id` 或会话类型，因此压缩摘要无法可靠区分“上一项英语”与“当前数学任务”。

**方案比较**

| 方案 | 优点 | 问题 | 结论 |
|---|---|---|---|
| 继续使用一个长期主会话 | 改动最少 | 任务串线、上下文越来越杂、压缩摘要仍持续占预算 | 不推荐 |
| 每个计划一个会话 | 会话数量较少 | 同一计划内多个任务仍会互相污染，切换任务不够干净 | 可用但不够彻底 |
| 主会话 + 每个任务一个任务会话 | 上下文最小、任务边界清楚、可独立恢复和评估 | 需要补会话类型、任务关系和自动切换 | 推荐 |

**推荐会话模型**

- `main` 会话：继续用于日常聊天、制定计划、修改计划和查看总结。
- `task` 会话：每个 `study_plan_item` 最多一个，由点击“继续学习”创建或恢复。
- 家长/老师现有多会话能力保持不变。

建议给 `chat_sessions` 增加：

- `session_type`: `main / task`
- `plan_id`: 可空，便于按计划查询任务会话
- `plan_item_id`: task 会话必填并唯一，保证重复点击只恢复同一会话
- `status`: `active / completed / archived`
- `context_version`: 记录当前加载的是计划第几个 revision，计划修改后可检测并刷新任务上下文

MySQL 5.7 的唯一索引允许多个 NULL，可以继续保留 `primary_student_id` 唯一主会话，同时给 task 会话使用 `plan_item_id` 唯一约束。

迁移时将现有会话统一回填为 `session_type=main`、`status=active`。学生初始化必须继续显式获取 `primary_student_id` 对应的 main session，不能再从普通会话列表里取第一条；学生会话列表默认排除 task session，避免任务会话挤占主会话入口。

**点击“继续学习”的自动流程**

1. 前端调用“继续计划任务”接口，只传 `plan_item_id`。
2. 后端校验任务属于当前学生、属于今天且未被移出。
3. 后端获取或创建该任务唯一 task session。
4. 前端自动切换到 task session，不展示会话选择负担。
5. 后端用内部 `TaskStartEvent(plan_item_id, context_version)` 调用 Agent；该事件不是学生消息，不在界面或聊天历史中伪造一条“用户说”。会话上的 `plan_item_id` 和 `context_version` 是持久化事实。
6. AI 根据任务上下文主动发第一条消息并正常持久化助手回复，学生不需要再输入或点击发送。
7. 再次进入同一任务时恢复原 task session；进入下一项时切换到另一个 task session。

**会话数量与数据库管理**

- 一个任务最多一个会话，不会因为重复点击无限创建。
- task session 通过 `plan_item_id` 直接查询，不扫描所有历史会话。
- 学生端不展示几十个会话列表；任务会话从 Today 任务进入。
- 任务完成后 session 标为 completed，消息保留用于学习证据和复盘，但不再注入其他任务。
- 任务重新打开时恢复原会话并新建一次 attempt，不新建重复 session。
- 不删除历史会话；后续如数据量变大，只归档消息展示，不改变学习证据。

### P1-3：需要建立任务级选择性上下文，而不是把所有记忆一次性注入

任务 AI 需要知道工具和关键学习事实，但不需要每轮拿到学生全部历史。

**任务会话固定注入**

- 当前学生身份和稳定画像短摘要。
- 当前计划 title、description、revision。
- 当前任务 title、target、minutes、related_tags。
- 当前任务的完成标准和最近一次 attempt 状态。
- description/context_refs 明确关联的素材、错题、笔记或历史计划摘要。

**按相关性少量注入**

- 与任务标签相同的 3-5 条代表性错题。
- 与任务相关的最近笔记或素材摘要。
- 今天和昨天的每日学习记录摘要。
- 历史未完成任务只在计划协商阶段使用，不默认灌入每个执行回合。

**按需工具读取**

- 素材全文：`list_materials / read_material`
- 全部错题：`query_error_book`
- 笔记详情：`query_notes`
- 历史计划：`query_study_plans`
- 正式试卷：练习卷生成和答题工具

**工具本身也要按任务裁剪**

- task session 只给学生任务所需工具，不加载家长管理、题库采集等无关工具 schema。
- 阅读任务可以有素材读取、提问、记录 attempt、生成练习卷等工具。
- 试卷任务可以有生成卷、开始答题、读取结果、记录 attempt 等工具。
- 工具集由服务端根据 `session_type + task type` 决定，模型不能自行扩大权限。

**预算原则**

- task session 不复用 main session 的滚动摘要。
- 计划 description 和任务 target 是稳定核心上下文，优先级最高。
- 其他上下文按来源分别设条数和字符上限。
- 完整内容由工具按需读取，避免每轮重复付费。

### P1-4：动态选择按钮需要成为独立通用能力

**问题性质**

这不只是计划页面加几个固定按钮，而是整个 Agent 的交互基础设施。目标学生很难把需求表达完整，系统必须主动给出清晰选项并引导选择。

**适用范围**

所有有限选项问题都必须优先使用动态按钮，例如：

- 今天有多少时间？
- 先学英语还是数学？
- 这个计划可以吗？
- 要做 5 题还是 10 题？
- 在线做还是下载 PDF？
- 这道题选择哪个答案？
- 继续练、换讲法还是先休息？
- 是否把错误题加入错题本？

**交互规则**

- AI 根据问题动态生成 2-4 个主要选项。
- 固定增加“都不符合，自己输入”。
- 有待回答选项时，普通文字输入框默认收起，减少学生犹豫。
- 点击“都不符合，自己输入”后再展开并聚焦输入框。
- 需要上传照片时保留相机/上传入口，不被隐藏。
- 点击普通选项后自动提交并触发下一轮 AI，不需要再点发送。
- 旧问题、已回答问题和过期问题不能再次点击。

**推荐基础设施**

新增通用 `present_choice_question`，不要直接把画像专用 `present_profile_question` 改成万能工具。前端复用现有 chips 组件，画像旧能力逐步迁移。

建议持久化 `chat_choice_interactions`：

- `id / interaction_id`
- `session_id / message_id`
- `question_type / question`
- `options JSON`
- `allow_custom_input`
- `status`: `pending / answered / expired / cancelled`
- `selected_value / custom_text`
- `expires_at / answered_at`

按钮回传 `interaction_id + option.value`，后端校验会话归属、状态和有效期，再转换成结构化 Agent 事件。正式状态变化仍由计划、试卷或任务 service 二次校验，不能只信按钮文本。

**强制使用方式**

- Prompt 明确要求有限选项问题必须调用该工具。
- 创建计划、修改计划、提交试卷等关键流程由后端 workflow 明确要求 choice interaction，不允许纯文本“可以”绕过。
- 增加真实 Agent live 测试，覆盖计划协商、任务执行和试卷选择，避免模型退回纯文本提问。

### P2-1：AI 试卷应作为独立执行能力接入任务

**当前断点**

- 现有正式 Exam 已支持题目、在线答题、交卷、判分和错题本。
- 现有照片批改已支持上传、识别、核对和批改。
- `create_exam` 只有家长/老师可调用，学生 task session 无法生成自练卷。
- Agent 创建 published 试卷后不会自动分发给当前学生，学生实际看不到。
- 聊天只显示普通工具摘要，没有“开始答题”行动卡。
- 正式结构化试卷没有一键 PDF 下载。
- 试卷没有关联 `plan_item_id` 和 attempt，交卷后不能自动回到任务流程。

**推荐能力**

新增受限的 `create_practice_exam`：

- 只允许学生为自己当前 task session 生成练习卷。
- 题目范围来自计划 description、任务 target、related_tags 和当前相关证据。
- 在一个事务中完成 Exam、Question、GradingRule、ExamAssignment 和计划任务关联。
- 不能传任意 student_id，后端从当前 task session 解析学生。
- 家长 Agent 出卷也必须在同一流程中明确分发给当前绑定学生。

**试卷行动卡**

生成成功后展示：

- 试卷标题、题量、预计时间和知识点。
- “开始在线作答”。
- “下载无答案 PDF”。
- “稍后再做”。
- “重新生成”需要再次确认，避免重复试卷。

**PDF**

- 新增学生版 PDF 下载接口，绝不包含答案。
- 优先复用后端已有 PyMuPDF 生成并流式返回文件。
- 必须嵌入随部署提供的中文字体，不能依赖服务器系统字体。
- 第一版只保证题干、选项、答题留白、分页和中文字体可用，不建设模板编辑器。
- 答案版只允许有权限的家长/老师获取。

**线下拍照作答**

- 上传必须携带原 `exam_id + plan_item_id + attempt_id`。
- 复用现有图片识别和学生作答核对面板。
- 识别出的答案映射回原试卷题目，不把照片当成一份新的未知试卷。
- 核对后使用原卷标准答案批改，再进入统一任务结果路由。

### P2-2：任务完成需要 AI 判定和结果路由

**正确原则**

“学生做了”不等于“任务完成了”。系统要根据任务的完成标准和学生提交的证据判断结果。

**可接受证据**

- 在线试卷答案和判分结果。
- 纸质作答照片及确认后的识别答案。
- 学生输入的文字答案。
- 学生描述的解题思路、阅读理解过程或总结。
- AI 追问后的口头/文字检查结果。

**推荐数据模型**

新增 `study_plan_item_attempts`：

- `id / plan_item_id / session_id / attempt_no`
- `evidence_type`: `online_exam / photo / text_answer / reasoning / material_check`
- `evidence_ref`：试卷记录、素材、图片批次或消息 ID
- `status`: `in_progress / evaluating / passed / needs_retry / blocked`
- `score / confidence`
- `feedback`：给学生看的判断和下一步
- `created_at / evaluated_at`

计划任务状态建议扩展为：

- `todo`
- `in_progress`
- `done`
- `skipped`

attempt 负责记录每次尝试，计划项只在某次 attempt 达到完成标准后变为 done。

**结果路由**

| 结果 | 路由 |
|---|---|
| 答案正确且达到完成标准 | attempt=passed，计划项=done，刷新每日记录，进入下一任务 |
| 有错误但适合继续练 | attempt=needs_retry，计划项保持 in_progress，AI 讲解后再出同类题 |
| 错误答案可形成错题 | 复用现有错题入库链路，关联 exam/question/attempt，再进入讲解或复练 |
| 学生思路部分正确 | AI 指出缺口并追问，不直接完成 |
| AI 判断置信度低 | 不落完成状态，继续追问或交给确定性试卷/人工核对 |
| 学生卡住 | attempt=blocked，记录卡点，给“换讲法 / 拆小一步 / 看示例 / 暂停”按钮 |

**判定边界**

- 客观题和正式试卷优先使用确定性判分，不让 LLM 覆盖标准答案。
- 开放题、思路和总结由 AI 按任务 target/rubric 评估，保存简明反馈和置信度，不保存内部推理链。
- 错题、笔记等长期资产继续服从现有确认和来源规则。
- 完成、错题写入、每日记录刷新要幂等，网络重试不能重复生成反馈或错题。

## 四、推荐实施顺序

基础设施优先，后续功能建立在同一套状态和路由上。

### 阶段 1：Today 和计划数据正确性（最高优先级）

1. Today 严格只查询今天计划。
2. AI 历史参考改用独立查询，不改变 Today 展示。
3. 修复创建计划后没有真实落库或没有刷新 Today。
4. 增加计划修改 API 和 Agent 工具。
5. 增加 plan description、context_refs、revision，并把创建/修改改成事务。
6. 创建计划后禁止自动开始学习。

这一步解决截图中最直接的错误，也为后续任务会话提供稳定数据。

### 阶段 2：通用动态选择能力

1. 建立 `present_choice_question` 和 choice interaction 状态。
2. 前端实现 2-4 个动态按钮 + “都不符合，自己输入”。
3. 点击后自动触发下一轮 AI。
4. 先接入计划制定、计划修改和是否开始任务。

这是所有低输入学习流程的共同底座，应该早于试卷开发。

### 阶段 3：任务会话与选择性上下文

1. 增加 main/task 会话类型和 plan_item 唯一关系。
2. 点击继续学习自动创建/恢复 task session。
3. 不产生可见的假用户消息，系统直接触发 AI。
4. 实现任务级上下文构建和工具裁剪。
5. 计划修改后向任务会话同步 context revision。
6. task session 独立压缩，不继承 main session 历史摘要。

### 阶段 4：attempt 和 AI 结果路由

1. 建立 `study_plan_item_attempts`。
2. 支持文字答案、思考过程和图片作为证据。
3. 实现 passed / needs_retry / blocked 路由。
4. 复用错题、每日记录和复练能力。
5. AI 不再通过学生自报直接完成任务。

### 阶段 5：正式试卷闭环

1. 修复现有试卷对象级权限。
2. 新增学生本人受限的 `create_practice_exam`。
3. 原子完成出卷、发布、分发、任务和 attempt 关联。
4. 增加试卷行动卡、在线直达和无答案 PDF。
5. 照片提交关联原试卷并进入 attempt 路由。
6. 在线交卷或照片批改后由统一结果路由判断任务是否完成。

## 五、关键状态矩阵

| 场景 | Today | AI 可见性 | 会话 | 任务状态 |
|---|---|---|---|---|
| 昨日计划未完成 | 不展示 | 制定新计划时可参考 | 不自动恢复旧任务会话 | 保留历史状态 |
| 今天没有计划 | 显示空态 | 可参考历史、画像和素材 | main session 协商 | 无今日任务 |
| AI 创建今日计划 | 立即展示 | 获得真实 plan_id | 仍停留 main session | item=todo |
| 学生修改计划 | 立即同步 | 使用新 revision | 已存在 task session 收到上下文更新 | 按修改结果更新 |
| 点击继续学习 | 展示当前项 | 注入当前计划和任务上下文 | 创建/恢复 task session 并自动回复 | item=in_progress |
| 切换到下一任务 | 当前项切换 | 不再注入上一任务会话 | 切换到下一 task session | 两项状态独立 |
| 提交错误答案 | 仍显示当前项 | 获得错误和证据 | 保持当前 task session | needs_retry/in_progress |
| 达到完成标准 | 自动选下一项 | 写入结果摘要 | 当前 task session completed | item=done |
| 试卷生成失败 | 保持当前项 | 给重试或换方式选项 | task session 保留 | 不改变 |

## 六、验收标准

### Today 与计划

- 逾期计划不出现在 Today，但 AI 制定新计划时能够引用其未完成内容。
- 今天无计划时，AI 确认创建后 Today 立即出现真实计划。
- AI 创建成功必须有真实 `plan_id`，不能只靠回复文案。
- 学生修改计划后，Today 和后续任务会话立即使用新版本。
- 每份新计划都有完整 description；每个任务都有 target。
- 创建计划后不会自动开始练习。

### 动态选择

- 所有有限选项问题显示动态按钮，不只显示纯文本问题。
- 每个问题有 2-4 个主要选项和“都不符合，自己输入”。
- 待选择时输入框收起；选择自定义后再展开。
- 点击选项自动提交并继续，不需要再点发送。
- 旧按钮、已回答按钮和过期按钮不能重复触发。

### 任务会话与成本

- 不同任务使用不同 task session，切换后不会继续上一任务内容。
- 点击继续学习后 AI 自动回复，页面中没有要求学生再发送的预填文本。
- 重复进入同一任务恢复原会话，不创建重复 session。
- task session 不携带 main session 的完整历史或滚动摘要。
- 注入内容能追溯到 plan description、item target 和相关来源。
- 无关素材、错题和工具不会默认进入每轮上下文。

### AI 完成判定

- 学生只说“做完了”不会直接把任务标成 done。
- 在线答案、照片、文字答案和思考过程都能形成 attempt。
- 错误答案进入 needs_retry，并按规则进入错题或继续练习。
- 达到任务完成标准后才标记 done，并自动进入下一项。
- 低置信 AI 判断不会改变正式完成状态。

### 试卷

- AI 生成的试卷真实落库、发布并分发给当前学生。
- 试卷行动卡可直接进入在线答题，不经过试卷列表二次选择。
- 学生可一键下载无答案 PDF。
- 照片作答关联原试卷并先核对识别答案。
- 交卷结果进入统一 attempt 和错误路由。
- 学生不能访问其他学生试卷，教师也不能越权修改其他教师试卷。

## 七、暂不做

- 不做复杂周/月日历排程。
- 不删除逾期计划、旧计划或任务会话。
- 不建设通用工作流引擎；只建设学习任务所需的 session、attempt 和结果路由。
- 不把开放式表达问题强行做成固定按钮；只有有限选项必须按钮优先。
- 不另建一套聊天专用题目、判分或错题系统。
- 不把学生全部历史素材一次性灌入每轮上下文。
- 不建设复杂 PDF 模板编辑器。

## 八、当前推荐结论

1. Today 只展示当天计划；逾期计划继续保留并供 AI 制定新计划时参考。
2. 计划需要新增持久化 description、context_refs 和 revision，并支持创建后的修改和实时同步。
3. 主会话只负责协商；每个计划任务使用一个可恢复的 task session。
4. 点击继续学习自动切换任务会话并触发 AI，不要求学生发送任何消息。
5. task session 使用选择性上下文和裁剪后的工具集，避免长期主会话持续膨胀。
6. 动态选择按钮是独立通用能力，所有有限选项问题统一复用，并提供“都不符合，自己输入”。
7. 任务完成由 AI 或确定性判分根据 attempt 证据判断，错误结果进入错题和复练路由。
8. 正式试卷是任务执行能力之一，建立在 task session、attempt 和结果路由之上，不单独再造流程。
