# 移动端绑定与主页今日计划体验设计

## 用户与问题

目标用户是主要用手机或平板打开知了的学生。真实使用反馈确认，学生需要从网页完成“复制绑定码、保存二维码、微信扫码连接 ClawBot AI、在 Bot 对话发送绑定码”四步流程。二维码负责在当前微信中连接学习助手，绑定码负责把当前微信身份与知了账号对应起来，两步不能合并，也不能只展示其中一步。

学生进入 `/chat` 后，首屏的大推荐横幅占用较多空间，却不能直接看到今天的真实计划和完成任务。手机端主要导航藏在抽屉里，“我的”也不是屏幕底部稳定入口。

## 成功标准

- 未绑定学生首次进入受保护页面时，直接看到轻量绑定引导；可以明确选择“今天不再提醒”，关闭后当天不再自动弹出，第二天恢复提醒并可立即使用主页。
- 绑定页先突出一次性绑定码和复制按钮，再展示可长按保存的临时二维码；四步说明必须按“复制绑定码 → 保存二维码 → 微信扫码 → 在 ClawBot AI 发送绑定码”的顺序出现。
- 进行中的本人绑定会话写入当前浏览器 `sessionStorage`；刷新或从微信返回后继续轮询同一会话。二维码过期时由现有 provider 会话刷新，绑定会话过期、身份冲突和网络失败都有可理解的重试或跳过入口。
- `/chat` 顶部显示真实“今日计划”：进度、最多 3 个到期或逾期计划任务、手动完成按钮和“查看全部计划”。没有计划时只预填一条与 Agent 商量今日计划的消息，不自动发送或创建计划。
- `< 768px` 显示固定底部导航“今天 / 学习 / 成长 / 我的”；四个常用入口一键到达，原有抽屉保留完整二级页面，不删除路由。
- 桌面侧栏改为较轻的暖色表面并适度收窄；聊天内容宽度和今日计划区域保持安静、可扫描，不再用整屏浅蓝推荐带。

## 绑定设计

### 状态与流程

1. `MainLayout` 仅对学生查询现有 `GET /api/channels/wechat/account`。已绑定或接口暂时失败时不打断主页。
2. 未绑定且当前账号今天没有关闭提醒时，显示绑定引导。引导自动创建或恢复本人绑定会话，先显示骨架，再按顺序显示绑定码、复制操作、二维码、四步说明和“今天不再提醒”。
3. 后端复用现有 `POST /v1/authorizations` 创建 iLink 临时授权会话，把 `qr_value` 和 `provider_session_id` 写入 `account_bind`，同时生成一次性绑定码；不增加第二套二维码服务或固定外链。
4. 前端每 3 秒串行轮询已有绑定会话接口。provider 确认扫码后，后端只把 `provider_account_id` 和当前扫码微信身份写入待绑定会话，不自动完成账号绑定；页面仍提示用户进入 ClawBot AI 对话发送已复制的绑定码。
5. 新连接的 Bot 在绑定会话有效期内允许扫码微信发送首条消息。收到绑定码后，后端复用 `complete_bind_by_code` 的渠道、Bot 账号、当前发送者微信身份、过期和唯一绑定校验，确认两次身份一致后才创建正式绑定。
6. Bot 运行时按 `provider_account_id + ilink_user_id` 隔离临时用户和正式用户，并可同时恢复多个已经绑定的 provider 账号；不能因新增扫码授权覆盖或断开现有学生的 Bot。
7. 家长邀请 `guardian_invite` 保持现有“扫码后发送绑定码”流程，不自动创建家长身份，避免扩大本增量的身份与隔离风险。

### 恢复与跳过

- `sessionStorage` 只保存当前用户的绑定会话 ID，不保存 token、二维码内容、绑定码或微信身份。
- `localStorage` 按当前用户只保存选择“今天不再提醒”的本地日期；日期与今天相同则不自动弹出，第二天日期不同后恢复提醒，不跨设备同步。
- 恢复失败、会话不存在或已过期时清理会话 ID，并允许重新生成。
- “今天不再提醒”只影响自动弹窗；个人中心仍可随时绑定。绑定成功后清理恢复会话和提醒日期。
- 后端身份冲突返回明确 `4xx detail`；前端停止无效轮询，显示错误、重新生成和跳过入口。

## 今日计划与页面布局

`TodayPlanPanel` 直接复用 `p2Api.listStudyPlans(studentId, 'active')` 和 `p2Api.updateStudyPlanItem`。它只选择 `planned_date <= 今天` 且仍有 `todo` 的计划，和现有 Learning Flow 到期边界一致；未来计划不伪装成今日任务。

面板把到期计划的任务按计划返回顺序与 `sort_order` 展平，最多显示 3 条。进度按这些到期计划中 `done` 或 `skipped` 的已处理项除以全部项计算。点击完成只更新用户明确点击的任务，成功后重新读取计划；失败时保留任务并显示错误。面板不提供自动完成、批量完成或自动跳过。

无到期计划时显示紧凑空态和“和助手定一下”按钮，只把“先询问时间和目标、给草案、确认后保存”的文字放进现有输入框。现有空会话的真实错题/学习入口保留，已有历史会话上方的大推荐横幅由今日计划面板替换。

移动端底部导航直接进入 `/chat`、`/study-plans`、`/learning-map`、`/account`；抽屉继续提供错题、笔记、素材、家庭陪伴和帮助等完整入口。底栏考虑 `safe-area-inset-bottom`，聊天高度和普通页面底部留出空间，不能遮挡输入框或按钮。

## 权限与数据边界

- 本人绑定只发生在已认证用户拥有的 `account_bind` 会话；越权会话在读取或刷新 provider 状态前返回 404。
- `complete_bind_by_code` 继续作为唯一写绑定关系的 service，不在 router 复制写表逻辑。
- provider 扫码确认只登记待绑定身份，不替代用户发送绑定码的明确操作；绑定码必须来自同一个 `provider_account_id` 和同一个扫码微信身份。
- 计划读取和计划项更新继续走现有后端权限校验；前端只隐藏不构成权限边界。
- 不读取 `.env`，不新增硬编码 URL、密钥、超时或业务阈值；现有轮询周期与二维码尺寸保留在前端交互层。

## 验收

- 后端：本人会话创建临时授权二维码；扫码确认后保持 `pending`，只有同一 Bot、同一扫码微信发送正确绑定码才变为 `bound`；多 provider adapter 可并存和重启恢复；错误 Bot、身份冲突、过期和重复使用返回明确错误；家长邀请保持原逻辑。
- 前端绑定：首次引导可选择今天不再提醒、同日重新进入不弹、次日恢复提醒、自动创建、绑定码可复制、二维码是可长按的真实 PNG `<img>`、四步说明顺序明确、刷新恢复、串行轮询、成功关闭、过期/网络/身份冲突可恢复；个人中心复用同一面板。
- 前端计划：加载、真实任务、完成刷新、空态只预填、错误重试、最多 3 项；家长不显示学生今日计划。
- 布局：主 Chrome 本地桌面和 `390x844` 检查底部导航、safe area、输入框、绑定码、二维码固定正方形、四步说明、今日计划、个人中心和无横向溢出；真实微信长按保存、从相册扫码、确认连接和发送绑定码单独记录是否完成。

## 暂不做

- 不改变家长邀请绑定码、双微信隔离、解绑和公众号绑定机制。
- 不持久化“跳过绑定”到后端，不把绑定变成登录硬门槛。
- 不把扫码确认直接当作账号绑定完成，不省略用户发送绑定码这一步。
- 不新增统一任务表、计划聚合 API、Flow Engine 或新的计划确认机制。
- 不自动创建计划、自动发送聊天、自动完成任务或删除任何旧页面。
