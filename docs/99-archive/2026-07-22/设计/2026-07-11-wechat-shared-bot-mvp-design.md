# 微信学习助手共享 Bot MVP 设计

## 目标

使用一个真实 iLink Bot 账号服务所有学生和家长。Bot 负责微信消息入口，知了继续负责账号、亲子关系、学情和提醒。不同微信用户的绑定、消息、登录链接、业务数据和 context token 必须隔离。

## 已确认决策

- 所有用户扫码后得到相同的 `ilink_bot_id`，不同用户拥有不同的 `ilink_user_id`。
- 整个微服务只运行一个共享 `WeixinAdapter`，不为每个用户创建 adapter。
- 用户扫码确认后进入三分钟临时白名单；发送正确绑定码后升级为长期白名单。
- 用户解绑后移出长期白名单，再次绑定必须重新扫码。
- Bot token 和 context token 使用 Hermes 文件存储，不进入知了数据库。
- context token 由 Hermes 按 `ilink_bot_id + ilink_user_id` 隔离。

## 身份模型

| 概念 | 字段 | 作用 |
|---|---|---|
| 微信渠道 | `channel=ilink_bot` | 与公众号历史绑定隔离 |
| 共享 Bot | `provider_account_id=ilink_bot_id` | 标识唯一 Bot 账号 |
| 微信用户 | `ilink_user_id` / `wechat_accounts.openid` | 标识 Bot 下的独立用户 |
| 知了账号 | `wechat_accounts.user_id` | 业务权限和数据归属 |
| 渠道会话 | `provider_account_id + ilink_user_id` | 消息和 context token 隔离键 |

该模型参考公司项目的通用渠道设计：`provider_account_id` 表示共享渠道账号，外部用户 ID 表示该账号下的用户，业务记忆最终按内部用户 ID 隔离。MVP 不复制公司的通用会话平台，只采用这组身份边界。

## 服务边界

### 微信 Bot 微服务

- 精确依赖 `hermes-agent[messaging]==0.15.0`。
- 创建和轮询用户扫码授权会话。
- 保存唯一 Bot 凭证并运行一个 `WeixinAdapter`。
- 维护临时白名单和已绑定用户白名单。
- 在转发入站消息前校验白名单。
- 将允许的文本消息转发给知了后端并回复一条文本；后端可通知微服务升级或移除该用户白名单。
- 接收后端主动发送请求，发送前再次校验目标用户仍在长期白名单。
- 将 provider 结果归一化为成功、窗口失效、会话失效或普通失败。
- 服务重启时恢复一个 adapter、Hermes context token 和有效用户白名单。

微服务不访问 MySQL，不查询学情，不判断亲子关系，不调用 Agent、LLM 或记忆系统。

### 知了后端

- 继续管理三分钟绑定码、一次性 H5 token、30 天 JWT 和 `teacher_students`。
- 保存 `channel + provider_account_id + ilink_user_id` 到现有微信表。
- 验证绑定码所属授权会话与入站 `provider_account_id + ilink_user_id` 完全一致。
- 处理学生登录、家长命令、真实学情摘要、提醒窗口和主动额度。
- 向微服务提供重启后需要恢复的有效微信用户列表。
- 解绑成功后通知微服务移除该用户白名单，不断开共享 adapter。

## 白名单状态

```text
未授权
  -> 扫码确认
临时白名单（绑定会话到期时间内）
  -> 正确绑定码
长期白名单（数据库 active 绑定）
  -> 用户解绑或绑定失效
移除白名单
  -> 再次绑定必须重新扫码
```

- 临时白名单只存在于微服务内存，并绑定授权会话和到期时间。
- 长期白名单以知了后端 active 绑定为唯一事实来源。
- 未进入临时或长期白名单的消息在微服务第一层丢弃，不转发业务后端。
- Hermes adapter 可以接收入站事件，但不能把 adapter 自带的单用户 `allow_from` 当成动态白名单。
- 白名单变化不重建 adapter，避免打断其他用户的长轮询。

## 主要流程

### 学生绑定与免登

1. 已登录学生在个人中心创建绑定会话。
2. 后端请求微服务创建扫码授权会话并返回二维码。
3. 学生扫码后，微服务获得共享 `ilink_bot_id` 和当前 `ilink_user_id`，加入临时白名单。
4. 后端轮询授权状态并把两项身份写入绑定会话。
5. 学生发送绑定码；后端校验渠道、Bot ID、用户 ID、有效期和一次性状态。
6. 绑定成功后，该用户进入长期白名单。
7. 学生发送 `进入工具`，获得一次性 H5 登录链接并进入 `/chat`。

### 家长绑定

1. 学生发送 `邀请家长`。
2. 后端只根据已有 `teacher_students` 生成三分钟邀请链接。
3. 家长在临时页扫码，进入同一个 Bot 的临时白名单。
4. 家长发送绑定码，后端再次校验家长账号和亲子关系。
5. 绑定成功后，家长可使用 `今日学情`、`提醒 09:00 20:30` 和 `关闭提醒`。

### 主动提醒

1. 现有每分钟脚本筛选到点、在窗口内且额度未耗尽的 iLink 家长账号。
2. 后端根据现有督促 service 生成一条合并摘要。
3. 微服务确认目标 `ilink_user_id` 仍在长期白名单，再通过共享 adapter 发送。
4. 只有明确成功才更新计数和提醒时间；窗口、额度、context token 或登录失效时暂停。

## 接口骨架

Bot 微服务保留五类最小接口：

- 创建授权会话。
- 查询授权状态和刷新后的二维码。
- 向 `provider_account_id + ilink_user_id` 发送文本。
- 移除指定用户白名单。
- 查询健康状态；运维停服时才停用共享 adapter。

知了后端提供：

- 接收入站微信文本并返回一条确定性回复。
- 返回共享 Bot ID 和全部有效 `ilink_user_id`，供重启恢复长期白名单。

所有地址、共享密钥、超时、窗口、额度、时区和 Hermes `HERMES_HOME` 都来自环境变量，不设置业务运行默认值。

## 凭证与恢复

- 唯一 Bot token 使用 Hermes `save_weixin_account` 保存，权限保持 `0600`。
- 微服务直接配置 Hermes 原生 `HERMES_HOME`，避免业务配置目录和 context token 目录不一致。
- Hermes `ContextTokenStore` 按 Bot ID 和微信用户 ID 分文件内容隔离并在 adapter 连接时恢复。
- 后端不返回 Bot token，也不在数据库、日志、接口错误或测试快照中保存 token。
- 重启时先读取唯一 Bot 凭证，再向后端读取 active 用户白名单，最后启动一个 adapter。

## 失败处理

- 扫码超时：刷新当前授权会话二维码，不扩大绑定码有效期。
- Bot ID 与绑定会话不一致：拒绝绑定。
- 微信用户 ID 与扫码用户不一致：拒绝绑定。
- 临时白名单过期：不再转发消息，要求重新扫码。
- 未绑定用户发送 `进入工具` 或家长命令：返回绑定提示，不创建账号或亲子关系。
- context token、Bot 登录或发送窗口失效：停止当前发送并返回结构化状态，不连续重试。
- 后端不可用：不回复业务结果，不把用户升级为长期白名单。
- 解绑通知微服务失败：数据库绑定仍失效，后端不再为该用户发起主动发送；该用户再次入站时后端拒绝业务操作并返回移除白名单指令，同时记录待诊断错误。

## 验收标准

1. 两个真实微信扫码后返回相同 `ilink_bot_id` 和不同 `ilink_user_id`。
2. 两个用户的入站消息、回复、登录链接、业务账号和 context token 不串联。
3. 未扫码用户、临时白名单过期用户和已解绑用户不能进入业务链路。
4. 绑定码过期、复用、跨渠道、Bot ID 不一致和微信用户 ID 不一致均拒绝。
5. 公众号与 iLink 绑定可同时存在，单渠道解绑互不影响。
6. 服务重启后只恢复一个 adapter，并恢复所有 active 用户和各自 context token。
7. 主动发送只能发给指定 active 用户，成功后才增加计数和更新时间。
8. 本地与公网真实浏览器覆盖个人中心、家长邀请页和 H5 登录页。

## 不做

- 不为每个用户创建 Bot 或 adapter。
- 不建设通用渠道平台、品牌管理或 Bot 昵称配置。
- 不接入 Agent、LLM、图片、语音、自动注册或亲子关系自动创建。
- 不做异常提醒、免打扰、详略模式、营销群发或长期 refresh session。
