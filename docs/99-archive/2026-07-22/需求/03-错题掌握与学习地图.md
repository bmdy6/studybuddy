# 错题掌握与学习地图需求

## 背景

错题是知了最核心的数据。当前系统已经能记录错题、错因、复盘笔记，但学生还看不到：

- 哪些知识点反复错。
- 哪些已经掌握。
- 哪些需要明天继续练。
- 自己的学习路径长什么样。

用户希望做成“学习地图”，让学生觉得很厉害，但第一版必须小而真实。

## 目标用户

- 学生：看见自己的薄弱点和进步。
- 家长：知道最近该督促什么。
- Agent：制定计划、讲题、推荐练习前优先看掌握状态。

## 要解决的问题

1. 错题只记录“错过”，没有清楚记录“后来掌握了吗”。
2. 知识点、错题、笔记、素材、计划反馈之间还没有可视化关系。
3. 学生缺少一个长期进步感页面。
4. Agent 的建议需要更稳定引用掌握状态，而不是每次重新总结。

## MVP 范围

| 能力 | 说明 |
|---|---|
| 掌握状态 | 每个知识点或错题聚合出红/黄/绿状态 |
| 复练记录 | 记录最近一次复练是否做对、错了几次、是否需要复习 |
| 学习地图页 | 用知识点节点展示相关错题、笔记、素材和计划反馈 |
| 点击下钻 | 点击知识点能看相关错题、复盘笔记、素材 |
| Agent 引用 | Agent 回答前能读取薄弱知识点和掌握状态 |

## 2026-07-07 MVP 实现记录

- 后端新增学习地图聚合服务，复用错题、笔记、已确认素材和学习计划项，不新增图数据库或掌握状态表。
- 新增 `GET /api/students/{student_id}/learning-map`，权限复用现有学生访问边界。
- Agent 新增 `query_learning_map` 工具，用同一套聚合结果回答薄弱点和下一步建议。
- 学生端新增“学习地图”页面，可查看知识点状态、行动建议和关联错题/笔记/素材/计划记录。

MVP 仍不做 AI 自动落库“已掌握”状态；绿色状态只来自可解释规则，例如完成相关计划且近期无错题。

## 暂不做

- 不引入图数据库。
- 不做复杂知识图谱自动推理。
- 不做全国课程标准全量知识点体系。
- 不做炫技动画压过学习内容。

## 复用要求

实现前必须先查并优先复用：

- 错题本的题目指纹、知识点字段、错因反馈。
- 笔记的 `source`、`source_ref`、`category`。
- 素材确认稿和最近素材摘要。
- 每日回顾和计划完成/跳过反馈。
- 前端现有图表库和设计 token。

第一版学习地图用 MySQL 聚合。只有当数据量、关系复杂度和查询需求证明 MySQL 不够，再评估 Neo4j、向量检索或 mem0。

## 验收标准

### 自动化验收

- 多道同知识点错题能聚合成同一薄弱点。
- 复练做对后掌握状态能从红变黄或绿。
- 删除或无权限数据不会出现在学习地图。
- Agent 上下文能读取掌握状态摘要。

### Codex 浏览器验收

1. 登录学生账号。
2. 进入学习地图。
3. 查看是否能看到知识点状态。
4. 点击一个薄弱点。
5. 确认能看到相关错题、笔记、素材。
6. 回到对话问“我最近最该补什么”。

通过标准：

- 学生能一眼看出薄弱点。
- 页面不只是图表装饰，能下钻到真实学习资料。
- Agent 建议和学习地图一致。

### 真人验收

真人重点看：

- 是否“看起来厉害”但又不浮夸。
- 学生能不能看懂红黄绿代表什么。
- 点击后是否能马上行动。
- 家长能不能看出今天该督促什么。

## 踩坑记录要求

以下情况必须记录：

- 知识点命名混乱导致重复节点。
- 页面图表遮挡、溢出或移动端不可用。
- Agent 编造不存在的掌握状态。
- 错题、笔记、素材权限混入别的账号。
