# 学习计划草案确认需求

## 当前状态

已完成并上线。当前文档保留为需求边界和验收口径参考，不再作为未实现需求排期。

已实现范围：

- 粗略学习意图先追问或生成草案，不直接创建正式学习计划。
- 最近有效草案被学生明确确认后才允许落库。
- 过期草案或无草案直接确认会被后端 guard 拒绝。
- 每日回顾未完成目标带入对话时，会明确提示先商量、确认时长和任务拆分，再创建计划。
- 本地 Codex 浏览器已验证“下午要学英语”不会直接落库，确认草案后计划页出现 2 个任务、60 分钟。

后续关联需求：

- 学习计划自动复盘：计划完成、跳过、逾期后，Agent 基于执行反馈生成复盘问题或明日调整建议。

## 背景

用户反馈过：学生只说“下午要学英语”，Agent 直接创建了 110 分钟英语计划，没有先问学生想怎么学、下午有多久、计划可不可行。这会让学生感觉被安排，而不是被陪伴。

学习计划必须从“AI 直接执行”改成“先商量，再确认，再落库”。

## 目标用户

- 学生：想让 AI 帮忙安排今天或某个时段学习。
- 家长：希望 AI 督促，但不希望计划不合理或过期后还持续干扰。

## 要解决的问题

1. 粗略意图不能直接创建计划。
2. 计划草案需要可确认、可修改、可拒绝。
3. 未确认草案需要短有效期，不能过几天还被执行。
4. 计划应能关联每日回顾里的“今日目标”和“需要督促”。
5. 逾期计划要进入复盘，不要长期挂在进行中制造焦虑。

## MVP 范围

| 能力 | 说明 |
|---|---|
| 计划意图识别 | 学生说“下午学英语”“今天想学数学”等，只进入商量流程 |
| 草案生成 | Agent 先问时长、目标、作业/考试压力；信息足够时生成草案 |
| 确认落库 | 只有学生明确“可以、确认、就这样安排”才创建计划 |
| 草案有效期 | 草案默认只在当天或短时间内有效；过期后需要重新确认 |
| 每日回顾联动 | 未完成目标可带到对话页，Agent 先商量计划 |
| 逾期复盘 | 逾期计划提供“复盘为什么没做”和“重新安排”入口 |

## 暂不做

- 不做复杂日历排程。
- 不自动读取手机日历或定位。
- 不做家长强制审批计划。
- 不做长期多周课程表生成。

## 复用要求

实现前必须先查并优先复用：

- 后端 `p2` 相关计划 service、router、schema。
- Agent 现有 `create_plan`、`list_plans` 或同类工具。
- 每日回顾已有“未完成目标带到对话”的入口。
- 站内通知和逾期提醒脚本。
- 前端已有学习计划页、每日回顾页、聊天页工具卡片。

如需新增草案模型，应优先复用现有计划字段和状态，不复制一套完整计划表。

## 验收标准

### 自动化验收

- 粗略学习意图不会直接调用正式创建计划工具。
- 明确确认后才允许创建计划。
- 过期草案不能继续落库。
- 每日目标带入对话时，prompt 包含“先商量再创建”约束。

### Codex 浏览器验收

1. 登录学生账号。
2. 在对话输入“下午要学英语”。
3. 观察 Agent 是否先追问或给草案，而不是直接说“已创建计划”。
4. 回复“可以，就按这个来”后，再确认学习计划页出现新计划。
5. 从每日回顾未完成目标进入对话，确认同样是先商量。

### 真人验收

真人重点看：

- 计划是否像和学生商量出来的。
- 时长和任务块是否合理。
- 学生是否能说“不行，改短一点”。
- 过期计划是否不再烦人。

## 踩坑记录要求

如果出现以下问题，必须记录到 `docs/本地验收踩坑清单.md` 或本文件：

- AI 又绕过确认直接创建计划。
- 草案有效期判断使用硬编码日期。
- 逾期天数和当前日期不一致。
- 测试数据污染正式学生账号。
