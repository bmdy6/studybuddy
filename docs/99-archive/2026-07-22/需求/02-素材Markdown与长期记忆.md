# 素材 Markdown 与长期记忆需求

> **兼容说明（2026-07-17）**：本文保留已实现的人工查看、修正和确认流程；每日教练新授权以 `12-每日教练与自动学习记录.md` 为准。高置信、非空的机器识别结果可以标记为 `machine_extracted` 自动保存并供 Agent 使用，但不能升级为 `verified` 或伪装成人工确认稿，`confirmed_markdown` 仍具有更高优先级。每日摘要可以客观写出“截至当前还有 N 项未完成”，这只是日报事实快照，不是新增一类独立催办或异常提醒。

## 背景

学生上传的素材是核心学习资产。它不只是“文件”，还应该变成：

- 学生能快速阅读的 Markdown。
- Agent 能长期读取的确认稿。
- 后续计划、讲题、复习、学习地图可以引用的依据。

用户已明确：素材应分为“原始素材”和“转换为 Markdown 的 AI 可读素材”，Markdown 素材学生也要能看到。

## 当前实现状态

2026-07-07 已完成图片素材 MVP：

- 图片素材可生成 Markdown 识别稿。
- 学生可查看并确认 Markdown，确认稿优先给 Agent 使用。
- Agent 已有 `list_materials` 和 `read_material`，能回答“我有哪些素材”并列出当前账号可访问素材、确认状态和标签。
- 最近素材摘要会进入 Agent 学习记忆，细节仍按需读取，避免把整篇 Markdown 硬塞进上下文。
- 线上 Codex 浏览器已验证：问“你看看我有哪些素材”时，Agent 调用 `list_materials` 列出 6 个素材，并说明 #712 已确认、其他素材待识别。

仍未完成：

- PDF、Word、纯文本等文档解析 provider。
- 更完整的长期记忆适配层，如后续可接 mem0 或向量检索，但业务事实仍以 MySQL 为准。

## 目标用户

- 学生：上传单词表、讲义、错题、课堂图片后，希望能复习、询问和整理。
- 家长：希望知道学生有哪些素材，必要时上传资料给学生。
- Agent：需要知道学生有哪些素材，并能在需要时读取确认稿。

## 要解决的问题

1. 当前素材页还没有清楚展示“原始素材 / Markdown 素材”双层结构。
2. Agent 有时会说“我目前还不能查看所有素材列表”，体验割裂。
3. 图片已能转 Markdown，但 PDF、Word、纯文本等 provider 未接入。
4. 机器识别稿可以带来源自动供 Agent 使用，但只有人工确认稿或其他可验证行为才能升级为更高等级事实。
5. 原图预览和 Markdown 阅读都要快，不能跳到错误域名。

## MVP 范围

| 能力 | 说明 |
|---|---|
| 双层展示 | 素材详情页展示原始素材预览和 Markdown 识别稿/确认稿 |
| Markdown 可读 | 学生可直接查看 Markdown 素材，加载快、排版清楚 |
| 确认流程 | 识别稿可确认，确认稿作为 Agent 优先读取内容 |
| 素材列表感知 | Agent 能回答“我有哪些素材”，列出当前账号可访问素材 |
| 最近素材摘要 | 近期素材摘要进入 Agent 学习记忆，但细节仍按需读取 |
| provider 预留 | 图片继续用现有通用 Markdown 提取内核；PDF/Word 后续接 provider |

## 暂不做

- 不把 PDF/Word 重型解析依赖直接塞进主后端。
- 不承诺所有扫描件都能完美识别。
- 不把机器识别稿伪装成人工确认事实，也不据此推导“已掌握”或“明显进步”。
- 不做全文搜索和向量库第一版。

## 复用要求

实现前必须先查并优先复用：

- `markdown_extraction_service` 和通用提取内核。
- 素材 upload、preview、permission 现有 router/service。
- Agent `list_materials`、`read_material` 工具。
- 前端 Markdown 渲染组件和素材管理页。
- 部署脚本里的素材识别字段补丁。

外部 provider 调研优先级：

1. Docling。
2. Marker。
3. MinerU。
4. Pix2Text。
5. 其他轻量 OCR/文档解析服务。

调研必须记录许可证、模型体积、速度、准确率、部署复杂度和失败回退方式。

## 验收标准

### 自动化验收

- 未确认识别稿不会被当作确认稿读取。
- 确认稿为空或空白时不能保存。
- `list_materials` 只列当前账号有权限的素材。
- `read_material` 优先返回确认稿，没有确认稿时明确提示状态。

### Codex 浏览器验收

1. 登录学生账号。
2. 上传真实学习图片。
3. 查看原图预览。
4. 生成 Markdown。
5. 确认 Markdown。
6. 在对话问“我有哪些素材”。
7. 再问“根据刚上传的素材整理重点”。

通过标准：

- 页面能同时理解原始素材和 Markdown 素材。
- Agent 能列出素材，并能读确认稿。
- 未确认内容不会被装作确定事实。

### 真人验收

真人重点看：

- Markdown 是否比原图更适合复习。
- 不确定或识别错的地方能否修改/拒绝。
- 上传后是否知道下一步点哪里。
- 预览链接是否稳定，不跳错站。

## 踩坑记录要求

以下情况必须记录：

- 浏览器上传真实素材失败。
- 识别超时或前端超时时间不够。
- 预览 URL 指向错误域名。
- PDF/Word provider 体积或速度不适合主服务。
- Agent 又回答“我看不到素材列表”。
