# 家长督促与定向分发需求

## 背景

智学伴里的家长不应该审批学生所有细节，比如兴趣爱好应由学生自己做主。但家长需要轻参与：

- 看最近反复错什么。
- 看计划有没有做。
- 看学生自己说哪里需要督促。
- 把练习、试卷或任务明确发给某个学生。

## 目标用户

- 家长：低成本了解学习情况，必要时发任务。
- 学生：不被过度控制，但能收到清楚的任务和提醒。

## 要解决的问题

1. 家长缺少“最近需要督促什么”的轻量视角。
2. 每周学习情况需要总结，但不能变成 AI 自嗨报告。
3. 试卷或练习需要定向发给某个学生，而不是所有人都看到。
4. 家长边界要清楚：不审批兴趣，只设置内容边界和督促。

## MVP 范围

| 能力 | 说明 |
|---|---|
| 家长督促面板 | 展示未完成计划、学生写的需要督促、近期高频错题 |
| 每周学习情况 | 生成“反复错什么 + 最近做了什么 + 下周建议”草稿 |
| 定向分发 | 家长发试卷/练习时选择学生 |
| 学生可见任务 | 学生端只看分发给自己的任务 |
| 权限校验 | 后端校验 teacher-student 绑定，不靠前端隐藏 |

## MVP 实现记录

- 后端新增 `/api/students/{student_id}/supervision-summary`，仅绑定家长可访问。
- 聚合未完成学习计划、每日回顾中的“需要督促的地方”、学习地图 weak 知识点和最近 `exam_assignments`。
- 学生详情页新增“督促面板”，并提供“去分发试卷”入口。
- 周报草稿只引用真实数据，不调用 LLM、不自动保存。

## 暂不做

- 不做家长审批兴趣。
- 不做复杂班级管理。
- 不做商业化多学生机构后台。
- 不做强提醒轰炸。

## 复用要求

实现前必须先查并优先复用：

- teacher-student 绑定和权限 service。
- 现有试卷、考试批次、作业分发或候选 `exam_assignments` 相关设计。
- 计划、每日回顾、错题和笔记聚合能力。
- 站内通知和定时提醒脚本。
- 家长端已有页面壳和表格组件。

定向分发必须优先扩展现有考试/试卷模型，不另写一套任务系统，除非 spec 证明现有模型不适合。

## 验收标准

### 自动化验收

- 家长只能看到绑定学生数据。
- 学生只能看到分发给自己的试卷/练习。
- 未绑定家长访问返回 403。
- 每周报告只引用真实错题、笔记、回顾、计划，不编造。

### Codex 浏览器验收

1. 登录家长账号。
2. 查看某个学生的督促面板。
3. 分发一份试卷或练习给指定学生。
4. 切换学生账号登录。
5. 确认学生端能看到该任务。
6. 换另一个未分发学生，确认看不到。

### 真人验收

真人重点看：

- 家长页面是否能一眼知道该提醒什么。
- 学生是否觉得任务来源清楚。
- 每周报告有没有引用真实数据。
- 家长参与是否不过度。

## 踩坑记录要求

以下情况必须记录：

- 账号切换后仍显示旧学生数据。
- 前端隐藏但后端未校验权限。
- 家长报告引用测试数据。
- 任务分发给错学生。
