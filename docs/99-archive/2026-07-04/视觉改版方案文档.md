# 知了 — 视觉改版方案文档

> 目标：在不重写功能、不改变主业务流程的前提下，把当前“功能框架可用”的界面升级成更像成熟学习产品的工作台。本文只记录当前视觉审计和改版方案；长期样式 token 仍以 `样式设计文档.md` 为准。

## 1. 改版结论

当前页面不是“丑”，而是**产品完成度不够**：导航和功能入口已经搭好，但空状态、数据摘要、工具栏、状态标签、操作入口和页面之间的一致性还不成熟。

优先级判断：

| 优先级 | 方向 | 原因 |
|---|---|---|
| P0 | 空状态与业务引导 | 多个页面当前只有一行灰字或空白卡片，用户不知道下一步 |
| P0 | 管理页工具栏 | 素材/试卷管理缺搜索、筛选、主操作按钮，像“只读表格” |
| P1 | 学生详情仪表盘化 | 学生页是家长视角核心，需要一眼看到学习状态 |
| P1 | Chat 首页工作台化 | `/chat` 是主入口，需要承载“下一步该做什么” |
| P2 | 视觉细节统一 | 圆角、卡片、行高、状态标签、hover/active 统一即可，不需要大改品牌 |

## 2. 成熟产品参考

参考不是照搬 UI，而是借它们的设计取舍。

| 产品 | 借鉴点 | 用在知了 |
|---|---|---|
| ChatGPT / Claude | 对话首页的空状态、快捷任务、输入区聚焦 | `/chat` 首屏从“空白聊天页”升级为“学习任务入口” |
| Linear | 低噪音侧栏、状态标签、紧凑表格、工具栏 | 试卷管理、素材管理、判分队列 |
| Notion | 安静内容密度、轻量空状态、文档式信息层级 | 笔记、素材、学习档案 |
| 飞书 / Google Drive | 文件管理工具栏、上传入口、筛选与批量操作 | 素材管理页 |
| Duolingo / Khan Academy | 学习进度反馈、鼓励感、学生画像温度 | 学生详情、学情诊断、错题反馈 |

设计定位：**安静的学习工作台**。不要做营销官网式 hero，不做紫蓝渐变，不做过度插画；重点是清楚、稳定、温和、有下一步。

## 3. 当前页面审计

### 3.1 Chat 首页

现状：
- 左侧导航和顶部栏结构清晰。
- 对话区空状态偏薄，只有会话标题、几条快捷问题和输入框。
- 缺少家长视角的“今日该处理什么”的工作台感。

建议：
- 顶部增加轻量欢迎区：当前孩子、最近学情、待处理事项。
- 快捷问题改为任务卡：查学情、出专项练习、整理素材、导入错题。
- 输入框保留底部聚焦，但增加“可上传素材/照片”的状态说明。
- 最近会话列表在空状态里露出，不只藏在下拉里。

### 3.2 学生列表

现状：
- 当前空状态只有“暂未关联孩子”，页面显得没完成。
- 标题“我的孩子”合理，但缺少添加/绑定入口和未来列表结构预期。

建议：
- 标题右侧放主按钮：`添加孩子` 或 `绑定孩子`。
- 空状态使用“说明 + 主按钮 + 未来卡片占位”。
- 有数据时使用学生卡片：头像/姓名、最近练习、错题数、待批改、进入详情。

### 3.3 学生详情

现状：
- 信息架构清楚：返回、标题、标签页。
- “学生 #2”编号感重，缺少真实学生身份和概览。
- 学习档案未初始化时过于空泛。

建议：
- 标题区改为学生 profile header：头像、显示名、角色/年级、最近更新时间。
- 顶部增加 4 个概览指标：掌握率、待处理错题、最近练习、待批改。
- 标签页下方空状态给出清晰行动：`去对话页生成学习档案`。
- 数据页用卡片+图表组合，不要一上来堆大表格。

### 3.4 素材管理

现状：
- 表格骨架清楚，但管理能力显得单薄。
- 上传入口不够显性。
- 缺搜索、筛选、批量操作、操作列。

建议：
- 页头右侧放主按钮 `上传素材`。
- 工具栏：搜索素材名/知识点、类型筛选、上传者/时间筛选。
- 表格列：名称、类型、知识点、上传人、上传时间、操作。
- 操作列使用图标按钮：预览、下载/打开、编辑标签、删除。
- 空状态引导上传真实学习资料。

### 3.5 试卷管理

现状：
- 只有 ID 和标题，缺少试卷管理必需的信息。
- 草稿/已发布等状态没有形成视觉层级。
- 顶部缺主操作入口。

建议：
- 页头右侧放 `导入试卷`，保留入口到 JSON/Agent 导入。
- 表格增加状态 tag、题目数、创建时间、最近作答、操作列。
- 操作列：预览、发布/归档、编辑、删除。
- 状态颜色克制：草稿灰、已发布蓝/绿、已归档灰。

### 3.6 判分队列

现状：
- 空白卡片，没有说明页面用途。
- 与“导入试卷 → 学生作答 → 待人工判分”的链路割裂。

建议：
- 空状态解释：暂无待人工判分题。
- 增加行动按钮：`去试卷管理`、`导入试卷`。
- 有数据时顶部显示队列统计：待判题数、涉及学生、最早等待时间。
- 列表按学生/试卷聚合，避免一堆散题让家长迷路。

## 4. 两档方案

### 方案 A：保守优化版

适合先落地，风险低。

- 不改主布局和路由。
- 补齐每个页面的标题区、空状态、主按钮。
- 表格增加状态 tag、操作列和更合理的行高。
- Chat 空状态改为任务卡。
- 统一卡片 padding、圆角、阴影、hover。

预计改动：
- `MainLayout.tsx` 少量细节。
- `ChatPage.tsx` 空状态和快捷任务。
- `StudentsPage.tsx`、`StudentDetailPage.tsx` 空状态/概览卡。
- `MaterialsPage.tsx`、`ExamManagePage.tsx`、`GradingPage.tsx` 工具栏/表格列/空状态。
- `index.css` / `designTokens.ts` 只补少量 token。

### 方案 B：明显升级版

适合确认方向后做第二轮。

- `/chat` 变成真正的学习工作台：左侧会话、中央对话、右侧孩子状态/待办。
- 学生详情做 dashboard：指标卡 + 图表 + 最近动态。
- 素材管理支持表格/卡片视图切换。
- 试卷管理支持分组视图：草稿、已发布、已归档。
- 全站增加更完整的 skeleton、错误态、空态插图体系。

风险：
- 改动更大，需要更完整浏览器回归。
- 可能触及现有页面结构和测试快照。

## 5. 推荐实施顺序

先做方案 A，再决定是否进入方案 B。

1. **统一页面骨架**
   - 页头：标题、副说明、主操作按钮。
   - 内容：工具栏、数据区、空状态。
   - 先改管理页，不碰复杂业务逻辑。

2. **补空状态**
   - 学生列表、学生详情、判分队列、素材空列表、试卷空列表。
   - 每个空状态都必须回答：这是什么、为什么为空、下一步做什么。

3. **升级表格和状态**
   - 素材管理、试卷管理、判分队列。
   - 增加状态 tag、操作列、时间列、统计文案。

4. **升级 Chat 首页**
   - 任务卡替代散落快捷文案。
   - 显示孩子上下文和待办。
   - 保持输入框核心地位。

5. **升级学生详情**
   - 头像/姓名/概览指标。
   - 学习档案未初始化时给强引导。
   - 已有数据时做 dashboard。

6. **浏览器回归**
   - 桌面 1280×720。
   - 窄屏/窗口缩小。
   - 家长端和学生端各走一遍。
   - 上传真实文件仍等真人测试时再做。

## 6. 设计约束

- 不做营销页式大 hero。
- 不使用紫蓝渐变、emoji 图标、发光阴影、装饰性圆球。
- 不把页面 section 包成一层又一层卡片。
- 管理页保持高扫描效率，信息密度高于官网，低于专业 BI。
- 主色继续用当前蓝色体系，成功/警告/错误只用于状态。
- 所有新增颜色、阴影、间距先放 token，不在页面散写。
- 所有新增按钮必须有明确 hover/active/focus 状态。

## 7. 验收标准

| 检查项 | 标准 |
|---|---|
| 空状态 | 每个空页面有解释、下一步入口、视觉占位 |
| 主操作 | 素材/试卷/判分等管理页一眼能看到主按钮 |
| 表格 | 有状态、时间、操作列；行高不过松 |
| Chat 首页 | 能看出它是学习任务入口，而不是普通聊天空页 |
| 学生详情 | 首屏能看到学生身份和关键学习状态 |
| 一致性 | 页头、卡片、表格、按钮、tag 风格统一 |
| 回归 | typecheck/lint/test/build + Codex 浏览器截图检查 |

## 8. 当前建议

先做 **方案 A：保守优化版**。它能用最小风险补上成熟产品最关键的“完成度”，尤其是空状态、工具栏、主操作按钮和状态标签。做完以后再看是否需要把 `/chat` 和学生详情升级到更强的工作台/仪表盘。
