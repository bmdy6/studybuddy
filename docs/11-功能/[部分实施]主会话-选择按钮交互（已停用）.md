# 主会话 选择按钮交互（已停用）

## 背景

选择按钮交互原本是主会话的核心交互方式：AI 需要学生在 2-4 个明确选项里做决定时（如先学数学还是英语、计划草案是否可行），调用 `present_choice_question` 工具，前端把选项渲染成可点 chips 按钮，学生点一下即可，不必打字。冷启动画像采集（年级、想提升的科目）用同类工具 `present_profile_question`。

设计意图是降低学生输入成本，让选择更轻量。

## 当前状态：已停用（2026-07-27）

按钮交互已停用，改为 **AI 正文直接列 1./2./3. 编号选项，学生回复数字或选项文字**。

停用后：
- AI 正常输出正文，不再只甩按钮不说话。
- 需要选择时，正文里列编号选项，学生回复"1"或选项内容即可。
- 冷启动画像问询也改成正文文字提问，不再弹按钮。

## 停用原因

按钮交互经过多轮修复仍频繁出问题（见 `docs/22-bug/[P2-中][已解决]主会话-AI正文复述选项问题导致重复.md`）：

1. **AI 正文被吞**：为避免选项卡 question 与正文重复，前端在有选择工具时整段隐藏 `msg.content`，结果 AI 正常引导语也被吞掉，界面只剩按钮或"思考中"，用户感觉 AI 不会说话。
2. **重复展示**：AI 偶发在正文复述 question/草案/选项，导致同一段内容出现两次（一次按钮卡、一次正文）。
3. **跨消息重复**：连续 assistant 消息出现相同按钮时，去重逻辑误删整条消息，连正文一起丢。
4. **任务会话跑题按钮**：`system_task.md` 的"去制定新计划/继续当前任务"按钮在无任务时出现，逻辑错误。

多轮修复（隐藏 question、渲染顺序、mergeToolNarrative 合并话术）都未能根治，且每次修复引入新回归。用户决定先停用按钮，让 AI 正常说话，用编号列表代替。

## 现在的替代方案

- **后端 prompt**（`system_student.md` / `system_parent.md` / `system_task.md`）：第 11 条改为"直接在正文用 1. 2. 3. 编号列选项，让学生回复数字或选项内容，不要调用按钮工具"。
- **前端兜底**（`MessageBubble.tsx`）：若 AI 仍调选择工具，把 `options` 渲染成"1. xxx 2. xxx 回复数字或选项即可"的文字列表（不可点），AI 正文照常显示。

## 残留代码

按钮工具的代码保留（方便以后恢复），但已不激活：

- **后端工具 schema**（`app/features/agent/tools.py`）：`_TOOL_PRESENT_CHOICE_QUESTION` / `_TOOL_PRESENT_PROFILE_QUESTION` 保留，description 标注"已停用，改用正文编号"。
- **后端 handler**（`app/features/agent/handlers/interaction.py` / `profile.py`）：保留。
- **前端 ChoiceCard 组件**：已删除。
- **前端回调链**（`onPickOption` / `onSendOption` / `onRequestManualInput` / `return_to_main`）：已删除。

## 恢复步骤（以后想恢复按钮时）

1. **前端**：在 `MessageBubble.tsx` 恢复 `ChoiceCard` 组件（可从 git 历史的 `fix/chat-experience-cleanup` 之前的版本找回）；恢复 `onPickOption` / `onSendOption` 回调链（`ChatMessageList` -> `ChatPage`）；`MessageBubble` 渲染 choice 工具时用 `ChoiceCard` 而非文字列表。
2. **后端 prompt**：第 11 条改回"必须调 `present_choice_question` 给可点按钮"。
3. **schema description**：去掉"已停用"标注，改回"给可点按钮、渲染成 chips"。
4. **测试**：恢复 choice 相关测试（按钮渲染、点击发送、去重）。
5. **务必先解决**：恢复前必须先解决之前"正文被吞/重复展示"的根因，否则会重现老问题。建议恢复时明确：按钮卡只承载按钮，AI 正文独立显示且必须存在；跨消息去重只抑制重复工具卡，不删整条消息。
