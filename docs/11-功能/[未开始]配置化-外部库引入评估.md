# 外部库引入评估（草稿）

> 扫描项目自实现通用功能，评估哪些值得引入开源库替代。本文件为草稿，后续择机引入，不与计划草案状态机混做。

## 现有依赖（已覆盖，不动）

- 前端：dayjs / axios / react-markdown / zustand / antd / recharts / qrcode.react
- 后端：bcrypt / PyJWT / openai / cos-python-sdk-v5 / pymupdf / pypdf / img2pdf / httpx

基础库覆盖已足够。

## 建议引入（2 个）

### tenacity
- **替换**：后端 4 处复制粘贴的重试逻辑（COS、LLM 调用、LLM 流式、agent_loop）+ 2 处熔断
- **现状**：同一个 `for attempt + sleep(2**attempt)` 模式写 4 遍，错误分类各写一遍，容易不一致
- **收益**：统一 1 套重试配置，减少约 80 行重复代码，改策略只改一处
- **注意**：agent_loop 的"已 emit 不重试"是业务逻辑，tenacity 只管建连阶段，流式中断重试保留
- **位置**：`app/utils/cos.py`、`app/core/ai_service.py`、`app/features/agent/agent_loop.py`

### rapidfuzz
- **替换**：`app/core/grading.py:64-80` 的 `_levenshtein` 手写动态规划算法
- **收益**：消除自维护算法代码，减少 bug 面
- **位置**：`app/core/grading.py`

## 不建议引入

| 库 | 考虑替换 | 理由 |
|---|---|---|
| axios-retry | 前端 withRetry | 简洁有测试，不绑 axios，引入需改 axios 配置 |
| dayjs duration | 考试计时器 formatTime | 3 行代码无 bug，加插件增 bundle |
| loglevel/pino | 前端 logger.ts | 30 行够用，接 Sentry 时再评估 |
| pybreaker/purgatory | 后端熔断 | 实现极简单进程，tenacity 钩子或内部统一即可 |
| structlog | 后端 logging_config | 标准 logging 合理，规模不值得迁移 |

## 不需引入库、内部统一（3 处）

1. `_format_dt` 重复 15+ 处 -> 抽 `app/utils/datetime.py`
2. `_sha256_hex` 重复 3 处 -> 抽 `app/utils/hash.py`
3. 熔断两套写法（类 vs 字典）-> 统一为一套

这三项是"先增内聚再解耦"，不需要第三方依赖。

## 时机

等计划草案状态机试点稳定后，再引入 tenacity / rapidfuzz + 内部统一 3 处。不与计划草案混做。
