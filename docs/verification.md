## 真实模型与浏览器

本轮实际调用 OpenAI `gpt-6-luna`，`reasoning_effort=none`；累计 **12 次**请求，包含定位首次使用问题前的 5 次，以及已有学习事实后的 1 次摘要刷新，未超出 12 次上限。MiMo 参数分支仅做了自动化回归，本轮没有调用 MiMo。

修复后用一个预填「七年级、数学」画像的虚构账号登录：只创建一个会话，没有因空学习记录调用摘要模型。在真实页面提出两项分数加法任务，Agent 经查询计划、错题和反馈后生成草案；人工点击「确认并创建」生成两项正式任务。点击「继续」进入任务专属会话，模型给出同分母加法讲解并提问。刷新后仍恢复同一任务和完整消息。

## 已知边界

- 已修复真实历史消息中的 LaTeX 原样显示：沿用 Markdown 管线接入 remark-math / rehype-katex，支持美元和括号定界符，保留代码原文，默认禁止不受信任的 LaTeX 命令，不启用原始 HTML。桌面与移动截图均使用同一历史消息刷新验收，没有为排版测试重新调用模型。KaTeX 固定到兼容 Node.js 20、已修复已知信任绕过公告的 0.18.2，传递依赖统一使用同版本。
- 已执行不跨主版本的 `npm audit fix`：生产依赖剩 2 项中风险（`react-router` / `react-router-dom` 6.30.6，公告范围为低于 7.18.0，npm 建议升级到 7.18.5）；全部依赖剩 1 项高风险（开发用 Vite 5.4.21，公告覆盖至 6.4.3，npm 建议升级到 8.3.7）和 9 项中风险。其余中风险包含开发用 TypeScript ESLint、minimatch、esbuild，需另做工具链兼容升级。未执行 `--force`，这不是全量安全审计，也没有确认每条公告在本项目可利用；例如本客户端使用 HashRouter，没有 SSR hydration。开发服务只绑定本机，不能当作公共生产服务运行。
- Docker Compose 与 GitHub CI 已提供，尚未在本次本地准备阶段实际运行；本机测试结果不能替代 MySQL 8.4 容器或远端 CI 结果。
- 微信 Bot、腾讯云 COS、视频转写、外部题源检索没有进行真实集成验收。默认微信关闭、本地文件存储可启动。
